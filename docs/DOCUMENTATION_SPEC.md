# Как писать документацию пакетов

Документация нужна пользователям плагинов и разработчикам, которые работают с пакетами этого репозитория. Описывайте действия и результат: что делает пакет, как его установить или подключить, где найти настройки и какие есть ограничения. Не повторяйте описание в нескольких разделах. Указывайте версии и названия параметров только после сверки с манифестом или кодом.

## Языки и файлы

- Основной язык - русский. Английская версия описывает те же действия и ограничения.
- `packages/<пакет>/README.md` - краткое описание, пример установки или подключения, ссылки на подробности и перевод. Для форка добавьте ссылку на исходный репозиторий.
- `packages/<пакет>/docs/README_EN.md` - английская версия README. Для остальных переводов используйте суффикс `_EN`: `Setup_EN.md`, `Features_EN.md` и т. д.
- `packages/<пакет>/assets/` - статические изображения и иконки пакета.

## Подробная документация

| Файл | Содержание |
| --- | --- |
| `Setup.md` | Установка плагина или подключение библиотеки, требования и команды разработки. В README и инструкции указывайте шаги и точный источник для DSH Desktop, а также команду установки для отдельного профиля CLI. Для библиотеки вместо этого опишите ее подключение. |
| `Features.md` | Возможности, параметры и ограничения. Стек и архитектуру указывайте там, где они помогают работать с пакетом. |
| `Examples.md` | Сценарии использования. Для плагина указывайте, где выполнить действие в DSH и какой результат ожидать; для библиотеки приводите пример импорта и использования. |
| `Security.md` | Работа с учётными данными, права доступа и другие ограничения безопасности, если применимо. |

В корневом [README](../README.md) перечисляйте все пакеты со ссылками и кратким описанием. Установку и команды, общие для нескольких пакетов, объясняйте в одном месте.

## Оформление

- Сохраняйте файлы в UTF-8 без BOM, с переводами строк LF.
- Указывайте язык в блоках кода (`text` для обычного текста).
- В README пакетов используйте абсолютные ссылки на GitHub: README может отображаться в DSH вне страницы репозитория. В `docs/` используйте относительные ссылки на файлы репозитория.
- Не добавляйте эмодзи, типографские кавычки, длинные тире и символы стрелок.
