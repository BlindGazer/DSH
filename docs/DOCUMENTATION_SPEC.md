# Стандарт документации пакетов DeepSeek Harness (DSH)

Техническое задание для оформления документации во всех пакетах монорепозитория `BlindGazer/DSH`.

## 1. Языки

- Основной язык документации: **русский**.
- Каждый пакет переводится на **английский**.
- Файл на русском: `<Name>.md`. Файл на английском: `<Name>_EN.md`.

## 2. Структура документации пакета

- `packages/<пакет>/README.md` - главный файл. Содержит минимум информации, потому что отображается в настройках плагина DSH (страница «Плагины»). Не должен быть перегружен.
- `packages/<пакет>/docs/` - вся остальная документация: подробные описания, переводы, скриншоты, примеры.
- Статические изображения и иконки: `packages/<пакет>/assets/`.

`README.md` - это визитная карточка пакета. Все подробности выносятся в `docs/`.

## 3. Содержание README.md

`README.md` должен быть коротким, но достаточным, чтобы читатель понял:

1. **Название и ссылка на репозиторий**: заголовок `# [@scope/пакет](ссылка на GitHub)`.
2. **Ссылка на GitHub**: блок-цитата `> [GitHub ...](...)`.
3. **Краткое описание**: 1-2 предложения, что это за плагин и для какой платформы (DeepSeek Harness).
4. **Назначение**: 2-3 предложения, зачем нужен и какую проблему решает.
5. **Установка из GitHub**: короткий пример команды `dsh plugin ... add github:...`.
6. **Технологический стек**: краткий список, что используется конкретно в этом пакете.
7. **Примеры в DSH**: как плагин выглядит и работает в интерфейсе. Если материала много - ссылка на `docs/Examples.md`.
8. **Ссылки на другие языки**: `[English](docs/README_EN.md)` и аналогичные.

## 4. Содержание docs/

Полная документация в `docs/` покрывает все секции:

- **Setup.md / Setup_EN.md**: установка (из GitHub через DSH CLI, через pnpm, из локальной папки) и доступные команды (build, test, check, verify и т.п.).
- **Features.md / Features_EN.md**: подробное описание, зачем нужен плагин и что он умеет, технологический стек, архитектура (слои `shared` / `host` / `client`).
- **Examples.md / Examples_EN.md**: примеры работы в DSH со скриншотами (как открыть настройки плагина, где отображаются данные, как выглядит).
- **Security.md / Security_EN.md**: дополнительная информация о безопасности (если применимо).
- **README_EN.md**: английский перевод главного README.

## 5. Полный перечень обязательных секций документации

В сумме (README + docs) документация пакета должна описывать:

- Название пакета.
- Ссылку на GitHub репозиторий.
- Краткое описание.
- Ссылку на оригинальный (upstream) репозиторий, если пакет является форком.
- Подробное описание: зачем нужен плагин и что он умеет.
- Технологический стек.
- Примеры в DSH: как открыть настройки, где отображаются данные, как выглядит.
- Дополнительную информацию (например, безопасность).
- Команды: установка локально, установка из GitHub, доступные команды (build, test, check).

## 6. Корневой README

- Корневой `README.md` содержит таблицу всех пакетов монорепозитория.
- Для каждого пакета: название, краткое описание и решаемые задачи, ссылка на README пакета.
- Ссылки ведут на `packages/<пакет>/README.md`.

## 7. Технические требования к файлам

- Кодировка: UTF-8 без BOM.
- Переводы строк: LF.
- Без emoji, em dash, стрелок и типографских кавычек в тексте (допустим ASCII).
- Блоки кода с указанием языка.
- В `README.md` ссылки должны быть абсолютными на GitHub (`https://github.com/BlindGazer/DSH/tree/main/...`), потому что README отображается в настройках плагина DSH, где относительные пути не работают.
- Во всех остальных файлах (`docs/`) ссылки должны быть относительными.
