# Design

## Context

См. `proposal.md` и `specs/router-absolute-resolver/spec.md`. Сейчас настройки проекта валидируют корень инструкций как относительный путь, discovery строит его от workspace, а проверки файловой системы считают выход за workspace небезопасным.

## Goals / Non-Goals

**Goals:**

- Разделить workspace root и instructions root в состоянии проекта.
- Сохранить полную обратную совместимость относительного режима.
- Безопасно читать внешний корень после канонизации пути и ссылок.
- Передавать агенту однозначную карту `@workspace` и `@instructions`.
- Настроить абсолютный режим вручную через существующий UI и project store.

**Non-Goals:**

- Копирование внешних инструкций в workspace.
- Автоматический redirect внешнего корня в `workspace/agents`.
- Хранение проектных настроек внутри каталога инструкций.
- Разрешение резервного discovery mode в абсолютном режиме.

## Decisions

1. **Независимые режимы в настройках.** `resolverMode` выбирает источник инструкций: `relative` использует workspace, `absolute` использует внешний `instructionsRoot`. Значение по умолчанию `relative`. `discoveryMode` отдельно определяет способ работы с источниками: `strict` использует основной источник, `merge` объединяет разрешенные источники, `fallback` использует запасной источник при недоступности основного. В `absolute` режиме разрешены только `strict` и `merge`; `fallback` отклоняется. В `merge` объединяются workspace и внешний `instructionsRoot`, при совпадении правило из внешнего корня имеет приоритет. Валидатор проверяет совместимость `resolverMode`, `instructionsRoot` и `discoveryMode`.

2. **Разделение корней без ограничения целей ссылок.** Discovery получает `projectRoot` и вычисленный `instructionsRoot`. В relative режиме оба совпадают по старой логике. В absolute режиме discovery ищет инструкции во внешнем instructions root, но symlink и junction внутри дерева разрешены, включая цели за пределами этого каталога. Для обычных путей проверяются только корректность, существование и доступность; отдельная проверка конечной realpath относительно корня не выполняется.

3. **Ограничение discovery mode.** В absolute режиме UI скрывает fallback, а серверная валидация также отклоняет его. При переключении режима UI выбирает merge, если текущий режим fallback, чтобы сохранение не создавало невалидную конфигурацию.

4. **Ссылки между корнями.** В теле Markdown-инструкций поддержать ссылки `@workspace/` и `@instructions/` как в обычном тексте, так и внутри Markdown-ссылок. `@workspace/` разрешается от workspace root, `@instructions/` от instructions root. Эти префиксы не применяются к frontmatter и настройкам. Голые относительные пути в absolute режиме считаются workspace-путями и сопровождаются предупреждением. `/agents/` считается устаревшим обозначением и диагностируется, но не подменяется молча.

4a. **Область действия правил.** Метаданные `paths` и `globs` из frontmatter сохраняют текущую семантику и всегда разрешаются относительно workspace root, включая absolute режим. Внешний instructions root меняет только источник discovery, но не область действия правила.

5. **Настройки проекта.** Использовать существующее хранилище project settings, индексированное каноническим workspace root. Это позволяет удалить workspace/agents, не теряя настройки и не создавая машинозависимый файл в репозитории. Некорректную конфигурацию нельзя сохранить: запись выполняется атомарно, а предыдущая рабочая настройка остается активной. В форме настроек акцентной является кнопка `Сохранить`, справа от нее расположена кнопка `Отмена`, доступная только при несохраненных изменениях. `Отмена` восстанавливает последнее сохраненное состояние формы.

6. **Состояние и диагностика.** API состояния текущей версии DSH обязательно возвращает `resolverMode`, `workspaceRoot`, исходный `instructionsRoot` и `resolvedInstructionsRoot`. Обратная совместимость со старыми формами ответа не требуется. Недоступный instructions root получает уровень `error` с кодом `instructions-root-unavailable` и временно отключает discovery и redirect. Отсутствующий отдельный файл получает уровень `warning` с кодом `instruction-file-missing` и не отключает роутер. После восстановления корня ошибка исчезает автоматически.

7. **Перенаправление.** Механизм изоляции не получает новую таблицу сопоставления. Если перенаправление включено, сохраняются существующие правила совпадения по `mainFile`, именам корневых файлов и каталогов. В absolute режиме назначение строится по тому же относительному имени внутри выбранного `instructionsRoot`. Symlink и junction в назначении разрешены, включая цели за пределами корня, если объект доступен. При отсутствующем или недоступном назначении исходное содержимое по-прежнему не раскрывается.

## Risks / Trade-offs

- [Внешний каталог недоступен] -> Проверять путь при сохранении и при discovery, но разрешать сохранять ещё не существующий каталог. При недоступном каталоге сохранять выбранный absolute режим, показывать понятную диагностику, временно отключать discovery и redirect до восстановления каталога, не передавать исходные инструкции. После восстановления продолжать работу автоматически.
- [Абсолютный путь машинозависим] -> Хранить его только в локальном DSH project store и показывать состояние пользователю; переносимость между машинами не обещать.
- [Старые голые ссылки неоднозначны] -> В абсолютном режиме сохранить совместимость как workspace-пути, но добавлять предупреждение и документировать явные префиксы.
- [Symlink ведет за пределы внешнего корня] -> Канонизировать конечную цель и пропускать объект с диагностикой.
- [Старые настройки discovery fallback] -> Нормализовать их только при смене на absolute и не допускать сохранения невалидной комбинации.

## Migration Plan

1. Выпустить код с default `relative`, не меняющий существующие проекты.
2. Пользователь вручную выбирает absolute в UI, задает внешний каталог и сохраняет настройки.
3. При невалидном внешнем корне проект остается в предыдущей рабочей конфигурации.
4. Откат выполняется переключением обратно в relative; существующий `workspace/agents` снова используется по старым правилам.
