# Spec Delta

## Purpose

Позволяет проекту использовать относительный корень инструкций внутри workspace или явно настроенный внешний каталог, сохраняя безопасное обнаружение правил и однозначные ссылки между двумя корнями.

## ADDED Requirements

### Requirement: Режим источника и режим обнаружения работают независимо
Система MUST отдельно учитывать `resolverMode` и `discoveryMode`. `resolverMode` выбирает источник инструкций, а `discoveryMode` определяет способ работы с разрешёнными источниками.

#### Scenario: Относительный источник
- **WHEN** выбран `resolverMode = relative`
- **THEN** workspace используется как источник инструкций, а `strict`, `merge` и `fallback` применяются по существующим правилам

#### Scenario: Абсолютный источник
- **WHEN** выбран `resolverMode = absolute` и задан внешний `instructionsRoot`
- **THEN** внешний каталог используется как основной источник инструкций

#### Scenario: Объединение источников
- **WHEN** выбран `discoveryMode = merge`
- **THEN** система объединяет workspace и внешний `instructionsRoot`, если оба источника разрешены текущим `resolverMode`, а при совпадении использует правило из внешнего корня

#### Scenario: Запрещенный резервный режим
- **WHEN** выбран `resolverMode = absolute` и `discoveryMode = fallback`
- **THEN** система отклоняет конфигурацию и не сохраняет её

### Requirement: Проект выбирает режим корня инструкций
Система MUST поддерживать относительный режим по умолчанию и абсолютный режим, выбираемый пользователем в настройках проекта.

#### Scenario: Старый проект открывается без новой настройки
- **WHEN** у проекта отсутствует настройка режима
- **THEN** система использует относительный режим и сохраняет поиск в workspace

#### Scenario: Пользователь включает абсолютный режим
- **WHEN** пользователь выбирает абсолютный режим и указывает существующий внешний каталог
- **THEN** система сохраняет выбор в проектном хранилище DSH и использует этот каталог после обновления

### Requirement: Абсолютный режим использует внешний корень
В абсолютном режиме система MUST обнаруживать инструкции по структуре настроенного внешнего корня. Symlink и junction внутри этого дерева разрешены, в том числе если они ведут к объектам за пределами внешнего корня. Для обычных путей система проверяет корректность, существование и доступность объекта.

#### Scenario: Инструкции найдены во внешней папке
- **WHEN** внешний корень содержит настроенные главным файлом, каталогом правил, каталогом навыков и конфигурацией областей элементы текущей структуры
- **THEN** система загружает их с теми же правилами и именами, что и в относительном режиме, но относительно внешнего `instructionsRoot`, без требования каталога `agents` в workspace

#### Scenario: Внешняя ссылка доступна
- **WHEN** файл или каталог внутри внешнего корня является symlink или junction и ведет к доступному объекту за пределами внешнего корня
- **THEN** система обрабатывает объект как обычный доступный путь и не блокирует его из-за расположения конечной цели

#### Scenario: Внешний корень недоступен
- **WHEN** настроенный внешний корень отсутствует либо недоступен
- **THEN** система сохраняет absolute режим, сообщает ошибку с кодом `instructions-root-unavailable`, временно отключает discovery и redirect и возобновляет их после восстановления каталога

#### Scenario: Обычный объект недоступен
- **WHEN** отдельный обычный файл или каталог отсутствует либо недоступен
- **THEN** система пропускает объект и сообщает диагностическое предупреждение с кодом `instruction-file-missing`, не отключая весь роутер

### Requirement: Режим обнаружения ограничен в абсолютном режиме
В абсолютном режиме система MUST разрешать только строгий режим и режим объединения; резервный режим MUST быть недоступен для сохранения и выбора в интерфейсе.

#### Scenario: Пользователь выбирает резервный режим
- **WHEN** абсолютный режим активен и пользователь пытается выбрать резервный режим
- **THEN** интерфейс не предлагает этот вариант, а серверная проверка отклоняет такую конфигурацию

### Requirement: Ссылки явно различают два корня
В абсолютном режиме система MUST разрешать `@workspace/...` относительно workspace и `@instructions/...` относительно внешнего корня инструкций. Ссылки поддерживаются в теле Markdown-инструкций как в обычном тексте, так и внутри Markdown-ссылок; frontmatter и настройки ими не обрабатываются. Метаданные `paths` и `globs` из frontmatter всегда разрешаются относительно workspace root.

#### Scenario: Ссылка на workspace
- **WHEN** правило содержит ссылку `@workspace/packages/dsh-core/src/`
- **THEN** ссылка разрешается относительно текущего workspace

#### Scenario: Ссылка на инструкции
- **WHEN** правило содержит ссылку `@instructions/front/skills/design-principles/SKILL.md`
- **THEN** ссылка разрешается относительно внешнего корня инструкций

#### Scenario: Старый путь без префикса
- **WHEN** правило в абсолютном режиме содержит голый относительный путь
- **THEN** система трактует его как путь workspace и сообщает предупреждение о необходимости явного префикса

### Requirement: Состояние показывает оба корня
Система MUST показывать пользователю активный режим, workspace root, исходный корень инструкций, resolved instructions root и диагностические сообщения. В API текущей версии DSH поля `resolverMode`, `workspaceRoot`, `instructionsRoot` и `resolvedInstructionsRoot` обязательны; поддержка старых форм ответа не требуется.

#### Scenario: Просмотр диагностики абсолютного проекта
- **WHEN** пользователь открывает состояние или диагностику проекта в абсолютном режиме
- **THEN** интерфейс отображает оба корня, режим и результат проверки внешнего каталога
