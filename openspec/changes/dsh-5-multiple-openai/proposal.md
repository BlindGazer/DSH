# Proposal

## Why

Сейчас плагин автоматически создает единственного провайдера OpenAI Codex. Пользователю нужны несколько явно созданных аккаунтов с независимой авторизацией и настройками, различимых на вкладке Models и в списке моделей беседы. Независимая маршрутизация прокси относится к следующей итерации, не к этому изменению.

## What Changes

- Не создавать провайдер автоматически. На вкладке Models показывать карточки созданных Codex-провайдеров и кнопку "+ Добавить OpenAI Codex аккаунт" после списка, включая пустое состояние.
- При создании запрашивать суффикс уникального идентификатора `openai-codex-<суффикс>` и отображаемое имя. Идентификатор состоит из строчных латинских букв, цифр и дефисов, проверяется хостом и после создания не меняется. Отображаемое имя можно переименовать без изменения авторизации и ссылок на модели.
- Карточка показывает краткие сведения и открывает модальное окно настроек, входа, переименования и удаления. Удаление требует подтверждения, удаляет учетные данные и настройки этой записи и снимает регистрацию ее моделей.
- Разрешить повторное создание удаленного идентификатора без восстановления прежних токенов и настроек. Сохраненные ссылки бесед на этот идентификатор будут относиться к новой записи; последствие должно быть явно указано при подтверждении удаления.
- Изолировать авторизацию, обновление токенов, модели, настройки, лимиты, сведения об использовании и операции с кредитами каждого аккаунта. Запрос использует только учетные данные выбранного провайдера; общего активного аккаунта и автоматической подмены нет.
- В инструментах агента требовать идентификатор для входа и выхода. Проверка состояния без идентификатора возвращает список имен, идентификаторов и состояний аккаунтов; с идентификатором проверяет выбранный аккаунт.
- Рядом с полем ввода сообщения показывать лимиты аккаунта выбранной модели. При выборе другого провайдера скрывать индикатор Codex.
- Регистрировать Codex-провайдеров в каталоге DSH отдельно с актуальными идентификаторами и именами, доступными существующему обнаружению прокси-плагина. Новый интерфейс выбора прокси не добавлять.
- **BREAKING** Удалить собственный переключатель подключения DSH / системного прокси Windows и соответствующий режим Codex. Использовать существующее подключение DSH, как в прежнем режиме DSH. Не реализовывать будущий API прокси, не переключать глобальный прокси для отдельных аккаунтов. Текущее ограничение маршрутизации по домену явно описать в документации.
- **BREAKING** При обновлении удалить прежний автоматически созданный провайдер, его авторизацию и настройки. Историю бесед сохранить; для старого маршрута требуется ручной выбор нового провайдера и модели, без автоматического назначения первого аккаунта.
- Агент выполняет автоматизированные проверки без реальных учетных записей, сборку и итоговое ревью, затем предоставляет инструкцию установки и чек-лист. Пользователь выполняет ручную приемку финального варианта после завершения всех задач агента; она не является условием закрытия этих задач.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `openai-codex-provider`: создание, переименование и удаление именованных провайдеров, независимые авторизация и операции, инструменты агента с явным выбором аккаунта, индикатор выбранного аккаунта и переход на существующее подключение DSH вместо собственного системного прокси.

## Impact

- Пакет `@kalex/dsh-openai-codex-provider`: хранилище записей и учетных данных, регистрация моделей, контракты клиент-хост и инструментов агента, интерфейс Models и индикатор лимитов, сетевой транспорт, миграция и тесты.
- Общие компоненты `@kalex/dsh-core` используются повторно; отдельный интерфейс выбора профиля прокси внутри Codex не создается.
- `dsh-6-proxy-by-provider` и использование его будущего контракта на стороне Codex полностью отложены; они не являются зависимостью или условием завершения `dsh-5`. Черновик следующей итерации: [draft.md](../dsh-6-proxy-by-provider/draft.md). Прокси-плагин в текущем изменении не перерабатывается.
- Существующий перехват по домену не обеспечивает разные прокси для Codex-аккаунтов с общими доменами. Появление отдельных строк провайдеров в окне прокси не означает сетевую изоляцию; ее проверка не входит в приемку этой итерации. Сетевые настройки браузера подтверждения входа не управляются плагином.
- Проверки охватывают параллельные запросы двух аккаунтов с разными учетными данными, обнаружение провайдеров, переименование и удаление без влияния на соседние записи, отсутствие регрессий существующих функций и сохранение обычного подключения DSH.
