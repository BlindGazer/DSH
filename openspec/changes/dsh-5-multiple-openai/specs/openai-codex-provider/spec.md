# Spec Delta

## MODIFIED Requirements

### Requirement: Пользователь может войти через ChatGPT и выйти из учетной записи
Плагин MUST предоставлять независимый вход ChatGPT через OAuth по коду устройства для каждого созданного провайдера. Учетные данные MUST храниться отдельно в локальном хранилище DSH, не передаваться клиенту и не использоваться другим провайдером.

#### Scenario: Вход через код устройства
- **WHEN** пользователь начинает вход из настроек выбранного провайдера
- **THEN** плагин показывает код и доверенную ссылку, сохраняет результат подтверждения в браузере только для этой записи и отображает ее состояние подключения

#### Scenario: Учетная запись отключена
- **WHEN** пользователь выходит из выбранного провайдера
- **THEN** его учетные данные удаляются, незавершенный вход отменяется, сведения об использовании очищаются, но карточка и настройки моделей сохраняются

#### Scenario: Истекший токен обновляется
- **WHEN** для операции выбранного провайдера нужен истекший или близкий к истечению токен
- **THEN** плагин обновляет и сохраняет токен только этой записи без раскрытия клиенту

#### Scenario: Параллельные входы независимы
- **WHEN** два провайдера одновременно проходят вход, а один из них выходит или получает ошибку
- **THEN** процесс и состояние второго не изменяются

#### Scenario: Запоздавшее обновление после выхода
- **WHEN** результат входа или обновления токена приходит после выхода или удаления соответствующей записи
- **THEN** результат не восстанавливает учетные данные и не изменяет другой аккаунт или новую запись с тем же идентификатором

### Requirement: Плагин предоставляет модели OpenAI Codex в DSH
Плагин MUST регистрировать отдельный маршрут и каталог моделей для каждой созданной записи, использовать учетные данные выбранного провайдера и сохранять поддержку уровней рассуждения, потоковых ответов и вложений DSH. Отображаемое имя провайдера MUST быть доступно в списке моделей беседы.

#### Scenario: Пользователь выбирает модель OpenAI Codex
- **WHEN** пользователь выбирает модель конкретного провайдера и отправляет запрос
- **THEN** запрос использует только его учетные данные и настройки, включая параллельные запросы одинаковой модели другого провайдера

#### Scenario: Нет действующего входа
- **WHEN** запрос отправлен через провайдера без действующих учетных данных
- **THEN** возвращается контролируемая ошибка авторизации без переключения на другой аккаунт

#### Scenario: Каталог обновляется
- **WHEN** пользователь создает, переименовывает или удаляет провайдера
- **THEN** каталог DSH отражает изменение без перезапуска процесса и не теряет регистрации соседних провайдеров

#### Scenario: Провайдер обнаруживается другими плагинами
- **WHEN** потребитель каталога DSH, включая существующее обнаружение прокси-плагина, получает список провайдеров
- **THEN** каждая созданная запись представлена своим идентификатором и актуальным отображаемым именем, а удаленная запись отсутствует

### Requirement: Пользователь настраивает список моделей
Плагин MUST позволять отдельно для каждого провайдера включать и отключать модели, менять их отображаемые имена и порядок, сохранять настройки между перезапусками и оставлять включенной хотя бы одну модель в каждой записи.

#### Scenario: Настройки моделей сохранены
- **WHEN** пользователь сохраняет допустимый список моделей одного провайдера
- **THEN** выбор, имена и порядок применяются только к его каталогу и сохраняются для следующего запуска

#### Scenario: Отключение последней модели
- **WHEN** пользователь пытается отключить последнюю включенную модель выбранного провайдера или отправляет недопустимый список
- **THEN** настройки не сохраняются и показывается понятная ошибка

#### Scenario: Одновременное сохранение
- **WHEN** настройки двух провайдеров сохраняются одновременно
- **THEN** оба изменения сохраняются без потери настроек соседней записи; при конфликте сохранения возвращается ошибка, а не ложный успех

### Requirement: Пользователь просматривает использование и сведения о кредитах
Плагин MUST показывать сведения об использовании, лимитах, сроках сброса и кредитах отдельно для выбранного аккаунта. Загрузка, ограничение, отсутствие данных и ошибка MUST различаться; данные другого аккаунта не подставляются.

#### Scenario: Данные использования доступны
- **WHEN** подключенный выбранный аккаунт возвращает данные использования
- **THEN** его карточка и настройки показывают доступные лимиты, остаток, сроки сброса и кредиты

#### Scenario: Данные использования недоступны
- **WHEN** запрос данных завершился ошибкой, ограничен или вернул неполные сведения
- **THEN** интерфейс обозначает недоступность или ограничение без подмены отсутствующих значений нулями

#### Scenario: Открыта другая карточка
- **WHEN** после переключения карточки приходит ответ для ранее открытого аккаунта
- **THEN** ответ не подменяет сведения текущей карточки

### Requirement: Пользователь подтверждает применение карточки сброса
Плагин MUST показывать карточки сброса и их сроки для выбранного аккаунта, требовать явного подтверждения расходования кредита и выполнять действие только с учетными данными этого аккаунта. Незавершенные операции MUST быть изолированы между записями.

#### Scenario: Подтверждено применение карточки
- **WHEN** пользователь выбирает карточку выбранного аккаунта, подтверждает действие и запрос завершен
- **THEN** плагин передает эту карточку с его учетными данными, показывает результат и обновляет только его сведения

#### Scenario: Результат применения неизвестен
- **WHEN** результат запроса нельзя определить достоверно
- **THEN** плагин сохраняет идентификатор того же запроса и карточку для повторной проверки в рамках той же записи и авторизации, не создавая новый запрос автоматически

#### Scenario: Смена или удаление аккаунта во время операции
- **WHEN** аккаунт вышел, повторно авторизован или удален до получения результата
- **THEN** запоздавший результат не изменяет новый сеанс или другую запись и не вызывает повторного расходования кредита; уже отправленное внешнее действие не объявляется отмененным гарантированно

### Requirement: Инструменты агента управляют входом
Плагин MUST предоставлять инструменты входа, проверки состояния и выхода с явным выбором идентификатора провайдера. Вход и выход MUST требовать идентификатор даже при единственной записи. Проверка без идентификатора MUST возвращать список имен, идентификаторов и состояний без токенов.

#### Scenario: Агент начинает вход и проверяет результат
- **WHEN** агент вызывает вход и проверку состояния с идентификатором существующего провайдера
- **THEN** вход возвращает код и ссылку, а проверка сообщает ход или результат именно этого входа без раскрытия токенов

#### Scenario: Агент завершает сеанс
- **WHEN** агент вызывает выход с идентификатором существующего провайдера
- **THEN** удаляется только его авторизация и последующая проверка показывает отсутствие входа

#### Scenario: Агент получает список
- **WHEN** агент проверяет состояние без идентификатора
- **THEN** возвращаются все записи с именами, идентификаторами и состояниями либо пустой список без автоматического создания аккаунта

#### Scenario: Отсутствующий или неизвестный идентификатор
- **WHEN** агент начинает вход или выход без идентификатора либо передает неизвестный идентификатор любой операции
- **THEN** возвращается понятная ошибка без выбора первого аккаунта, создания записи или изменения существующих авторизаций

### Requirement: Перенос сохраняет совместимость текущих установок
Пакет MUST сохранять свои идентификаторы установки и сведения об авторстве и лицензии. Исключение для перехода к нескольким аккаунтам: прежний автоматический провайдер, его авторизация и настройки MUST удаляться без переноса в новую запись; новые пользовательские записи сохраняются при последующих запусках.

#### Scenario: Обновление установленного плагина
- **WHEN** установка с единственным автоматически созданным провайдером обновляется до этой версии
- **THEN** старые учетные данные и настройки очищаются, автоматическая запись не создается, пользователь получает объяснение необходимости создать аккаунт и войти заново

#### Scenario: Повторный запуск и прерванная миграция
- **WHEN** очистка запускается повторно или возобновляется после сбоя
- **THEN** она затрагивает только старые данные, не удаляет новые записи и не объявляет завершение до успешной очистки

#### Scenario: Старая беседа с удаленным маршрутом
- **WHEN** беседа ссылается на старый автоматический маршрут
- **THEN** история остается неизменной, пользователь должен выбрать новый провайдер и модель, а запрос не перенаправляется автоматически

#### Scenario: Разворачивание пакета
- **WHEN** читатель устанавливает или обновляет пакет по документации
- **THEN** имя пакета указано как `@kalex/dsh-openai-codex-provider`, сохранены авторство и лицензия, описаны повторный вход и невозможность восстановления удаленной авторизации откатом

## REMOVED Requirements

### Requirement: Пользователь выбирает сетевой маршрут запросов
**Reason**: Собственный режим системного прокси Windows и переключатель Codex исключены пользователем; независимая маршрутизация по провайдеру отложена в dsh-6.
**Migration**: Плагин MUST использовать существующее подключение DSH. Прежняя настройка системного прокси удаляется при миграции; новый интерфейс выбора профиля внутри Codex не добавляется.

## ADDED Requirements

### Requirement: Пользователь создает именованные провайдеры OpenAI Codex
Плагин MUST создавать провайдеры только по действию пользователя с суффиксом идентификатора и отображаемым именем. Полный неизменяемый идентификатор имеет префикс `openai-codex-`; суффикс непустой и содержит только строчные латинские буквы, цифры и дефисы. Хост MUST отклонять занятый идентификатор и пустое после удаления крайних пробелов имя.

#### Scenario: Создание провайдера
- **WHEN** пользователь нажимает "+ Добавить OpenAI Codex аккаунт", вводит допустимый суффикс и имя и подтверждает создание
- **THEN** после успешного сохранения появляется отдельная неавторизованная карточка с именем и полным идентификатором; вход сам не начинается

#### Scenario: Пустая секция
- **WHEN** пользователь открывает Models без созданных аккаунтов
- **THEN** список Codex пуст, кнопка добавления доступна под секцией и автоматические создание и авторизация не выполняются

#### Scenario: Ошибка или отмена создания
- **WHEN** введены недопустимые данные, занят идентификатор, сохранение не удалось или пользователь отменил форму
- **THEN** новая запись и авторизация не появляются; ошибка отображается для недопустимых данных или сбоя сохранения, отмена не меняет состояние

#### Scenario: Совпадение отображаемых имен
- **WHEN** пользователь создает записи с разными идентификаторами и одинаковыми отображаемыми именами
- **THEN** обе записи допустимы и различимы по идентификаторам без смешения настроек и моделей

#### Scenario: Перезапуск
- **WHEN** DSH перезапускается после создания и настройки нескольких аккаунтов
- **THEN** записи восстанавливаются с прежними идентификаторами, именами, привязками авторизации и настройками; дополнительная автоматическая запись не появляется

### Requirement: Пользователь управляет отдельной карточкой провайдера
Плагин MUST показывать все созданные Codex-провайдеры карточками на вкладке Models и кнопку добавления после списка. Карточка MUST открывать модальное окно только своей записи с авторизацией, сведениями, настройками моделей, переименованием и удалением.

#### Scenario: Открытие карточки
- **WHEN** пользователь активирует карточку мышью или клавиатурой
- **THEN** открывается доступное модальное окно нужной записи; другие карточки и их авторизации не изменяются

#### Scenario: Переименование
- **WHEN** пользователь сохраняет новое непустое отображаемое имя
- **THEN** новое имя сохраняется и отображается в Models и выборе моделей беседы, а идентификатор, учетные данные, настройки и ссылки бесед не меняются

#### Scenario: Попытка изменить идентификатор
- **WHEN** пользователь просматривает настройки созданного провайдера или клиент пытается изменить его идентификатор
- **THEN** идентификатор доступен только для чтения, а хост не принимает его переименование

### Requirement: Пользователь удаляет провайдера и может повторно использовать идентификатор
Плагин MUST удалять выбранную запись только после подтверждения, очищать ее учетные данные и локальные настройки, отменять незавершенный вход и снимать регистрацию моделей. Удаление MUST не затрагивать другие записи. Повторное создание того же идентификатора разрешено без восстановления старых данных.

#### Scenario: Подтверждение удаления
- **WHEN** пользователь запрашивает удаление
- **THEN** показываются имя и идентификатор, предупреждение об удалении авторизации и о том, что повторное использование идентификатора свяжет старые беседы с новой записью; отмена ничего не меняет

#### Scenario: Удаление завершено
- **WHEN** подтвержденное удаление успешно завершено
- **THEN** карточка, модели, учетные данные и настройки удалены; история бесед сохранена, а запрос к отсутствующему провайдеру не использует соседний аккаунт

#### Scenario: Сбой очистки
- **WHEN** удалить учетные данные или сохранить удаление не удалось
- **THEN** интерфейс сообщает ошибку, не показывает ложный успех и позволяет безопасно повторить очистку без затрагивания других аккаунтов

#### Scenario: Повторное создание
- **WHEN** пользователь создает провайдера с идентификатором ранее успешно удаленной записи
- **THEN** появляется новая неавторизованная запись с начальными настройками; старые беседы с этим идентификатором относятся к ней, но запоздавшие операции прежней записи не могут изменить ее состояние

### Requirement: Индикатор лимитов соответствует выбранной модели беседы
Плагин MUST показывать рядом с полем сообщения лимиты только аккаунта выбранной Codex-модели и скрывать индикатор для других провайдеров или отсутствующей записи.

#### Scenario: Переключение модели или беседы
- **WHEN** пользователь выбирает модель другого Codex-аккаунта или переключает беседу
- **THEN** индикатор относится к текущему выбранному аккаунту; данные прежнего аккаунта не показываются как новые даже при запоздавшем ответе

#### Scenario: Нет подключения
- **WHEN** выбранный Codex-аккаунт не авторизован или данные недоступны
- **THEN** интерфейс не показывает лимиты другого аккаунта; отсутствие входа или данных не подменяется нулевым остатком

### Requirement: Codex использует существующее сетевое подключение DSH
Плагин MUST выполнять серверные сетевые операции через существующее подключение DSH без собственного режима системного прокси и без переключения глобального маршрута между аккаунтами. Эта итерация MUST не требовать API dsh-6 и не заявлять независимые прокси для общего домена.

#### Scenario: Обычное подключение
- **WHEN** выполняются вход, обновление токена, запрос модели, получение лимитов или операция с кредитом
- **THEN** используется существующий сетевой механизм прежнего режима DSH без обязательной установки прокси-плагина и без запуска собственного системного прокси Codex

#### Scenario: Ограничение прокси текущей версии
- **WHEN** пользователь читает документацию о нескольких аккаунтах и видит их в списке маршрутизации прокси
- **THEN** явно указано, что обнаружение аккаунтов не гарантирует разные прокси для общих доменов и что независимая маршрутизация отложена в dsh-6
