# Design

## Context

OpenAI Hub выбирает язык в apply, Router сохраняет начальное предпочтение оболочки, Proxy Provider загружает отдельную настройку. Workspace Manager и Logger уже используют locale.bind: им нужна проверка обновления смонтированного интерфейса, а не новый переводчик.

## Goals / Non-Goals

Core описывает общую интеграцию, DSH владеет языком и словарным реестром, каждый плагин владеет своими строками. Не менять механизм выбора языка оболочки, не переводить пользовательские данные и записи журнала задним числом.

## Decisions

- Представить в Core типы пространства имен, перевода с параметрами, регистрации и активной локали. Не ограничивать активную локаль двумя языками словаря. Не копировать реестр, выбор резервного языка или настройки в Core.
- При активации регистрировать словари с освобождением регистрации при выгрузке. В регистрации локализованного слота указывать пространство имен, переводчик получать от DSH. Для подписей вне рендера использовать функцию, вызывающую bind-переводчик при показе, а не готовую строку из apply.
- Использовать обновления рендерера слотов. Только для потребителей вне этой границы, которым нужен реактивный снимок, использовать getSnapshot/subscribe через Core. Для форматирования брать active, а не сохраненное preference. Не пересоздавать контроллеры и формы при смене языка.
- В Proxy Provider заменить перевод уже собранных динамических фраз ключами с параметрами. Убрать чтение и запись старого выбора языка Proxy и Router, поля интерфейса и конфигурации. Устаревшее поле при загрузке не должно приводить к сбросу всей конфигурации.

## Risks / Trade-offs

Стабильная ссылка на переводчик сама по себе не вызывает рендер. Проверять открытую панель и дочерние компоненты при переключении без обновления данных. Изменения публичных типов Core проверять сборкой всех потребителей; старые экспорты не удалять без проверки совместимости.

## Migration Plan

Сначала общий контракт Core, затем переход пяти клиентов и удаление локальных настроек. Проверить переключение в обе стороны, запасной перевод, форматирование и повторную активацию. Обновить правила для будущих плагинов. Для отката вернуть предыдущие клиентские сборки и совместимую версию Core; удалять данные профиля для миграции не требуется.
