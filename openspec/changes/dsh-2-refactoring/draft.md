Конечная цель все работы над этим проектом:
Написать демонстрационный проект по разработке красивых, стандартизированных, поддерживаемых (в долгой перспективе) плагинов DSH (или просто NPM пакетов)
Важные моменты которые должен показать этот проекта:
- Единную стукруры множества небольших npm проектов
- Разработку требования агентами с помощью openspec
- Использования единного механизма хранения и написания правил для агентов(skills / rules), с разграничением по областям, чтобы не загружать все правила глобально а автоматически подгружать по мере работы с нужными областями

Текущие проблемы:
- Проект не использует единную архитектуру
- Есть дублирование кода
- Нет возможности переиспользовать общие компоненты, стили, методы и т.п.
- Нет единной системы дизайна
- Не используются хорошие практики паттернов проектирования SOLID
- Есть расхождения со стандартной стилизацией DSH
- Отсутствуют статичиские методы анализа и проверки кода
- Текущий стек: javascript, react (очень старая версия),

Задача:
- Разработать и применить единную архитектура хранения файлов и папок для всех проектов.
- Разработать систему дизайна с цветовыми палитрами, которая будет переиспользоваться во всех проектах, иметь возможность добавления новых тем и давай возможно переопределять стили в конкретных проектах/компонентах
    - Эта система дизайна должны придерживать 2 критериев, быть в основной стилистика DSH чтобы пользователь не мог отличить где заканчивается интерфейс DSH а где начинается интерфейс плагина
    - Придерживаться лучших принципов по разработке удобного интферфейса google (т.е. найти современные стандарты, которые не будут противоречить DSH)
- Перенести код на желаемый стек:
    - React >= 19.3.1 + react-compiler
    - vite >= 8.3.5
    - vitest
    - typescript >= 7.0.2
        - нужна жесткая типизация без использования any/unknown и т.п.
    - eslint >= 10.14.0 + prettier >= 3.9.10
        - вместо eslint или prettier могут быть использованы альтернативные инструменты, если есть объективные причины замены, типа скорости работы
- Внедрить средства автоматизации для проверки и форматирования кода. Цель - агент не должен тратить ресурсы на то, что можно проверить и исправить автоматически
    - Применить для статических анализаторов (типа eslint.configs.recommended, seslint.configs.recommendedTypeChecked, react.configs.flat.recommended, reactHooks.configs.flat.recommended)
    - Применить для форматеров кода рекомендуемые правила, с поправкой для Prettier для следующих опций
    "semi": true,
    "printWidth": 140,
    "tabWidth": 4,
    "singleQuote": true,
    "trailingComma": "none",
    "arrowParens": "avoid",
    "bracketSameLine": true
    - Написать скрипты, которые будут автоматически запускать анализ кода, автоматическое исправление и форматирование того, что можно исправить. И вывод ошибок для того, что исправить нельзя.
- Внедридь единный подход для переиспользования общего кода и компонентов
    - Вынести общий код, комопненты, локализацию, скрипты и другую общую логику, котоаря переиспользуется в dsh-provider-proxy и dsh-agents-router в общий проект dsh-components (@kalex/dsh-components), если components не уместно, используй другое название
        - Этот общий проект должен тоже должен иметь полноценный цикл, с билдом и тестами, и иметь возможность публикации
    - в проектах dsh-agents-router и dsh-provider-proxy, подключить dsh-components без зависимости pnpm, т.к. все эти репозитории находятся локально, хочется чтобы код им был доступен без установки внешнего пакета, а напрямую. Т.е. во внешних проектах dsh-components должен быть доступен как внешний проект, а в рамках одного репозитория напрямую
