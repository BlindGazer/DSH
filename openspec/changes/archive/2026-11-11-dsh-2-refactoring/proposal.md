# Proposal

## Why

Проекты в репозитории используют разрозненную структуру каталогов, устаревший стек на JavaScript без строгой типизации и разные способы сборки клиентской части. Между плагинами дублируются компоненты интерфейса, логика определения темы, словари локализации и вспомогательные функции, отсутствует общий пакет для переиспользования кода и нет автоматизированной статической проверки с автоисправлением ошибок. Кроме того, правила для агентов требуют четкого разделения по областям разработки, чтобы контекст сессии не перегружался правилами, не относящимися к текущей задаче.

## What Changes

- Организовать единую структуру монорепозитория с размещением всех пакетов в каталоге `packages/`: общий пакет `@kalex/dsh-core` (`packages/dsh-core`), плагин маршрутизации правил `@kalex/dsh-agents-router` (`packages/dsh-agents-router`) и плагин проксирования `@kalex/dsh-proxy-provider` (`packages/dsh-proxy-provider`).
- Вынести общие компоненты интерфейса, систему дизайна, цветовую палитру с поддержкой тем, локализацию, хуки, модели и утилиты в пакет `@kalex/dsh-core` с собственным циклом сборки, тестирования и возможностью отдельной публикации, обеспечив при этом прямое подключение исходного кода внутри репозитория без установки внешнего пакета.
- Перевести все пакеты на единую послойную архитектуру (`shared`, `host`, `client` с разделением по функциональным модулям и принципам единственной ответственности и открытости-закрытости) и современный стек: React (не ниже 19.3.1) с автоматической оптимизацией через компилятор React в Vite (не ниже 8.3.5) и минификатором Oxc, строгий TypeScript (не ниже 7.0.2) без нетипизированных конструкций и модульные тесты на Vitest.
- Внедрить автоматизированную проверку, автоисправление и форматирование кода с помощью Biome и Oxlint (включая правила компилятора React и проверку типов) и единый стандарт кодировки UTF-8 без метки порядка байтов с переводом строки LF.
- Структурировать правила и навыки для агентов в каталоге `agents/` по областям (общие правила, фронтенд и дизайн-система, серверная часть плагинов, тестирование, спецификации) с автоматической маршрутизацией подгрузки только нужных правил.

## Capabilities

### New Capabilities

- `monorepo-architecture`: Единая модульная архитектура пакетов в `packages/`, прямое переиспользование общего пакета `@kalex/dsh-core` внутри репозитория, автоматизированный контроль качества кода и контекстное разграничение правил для агентов по областям.

### Modified Capabilities

- `theme-consistency`: Расширение единой системы дизайна с поддержкой палитр DSH и принципов удобства интерфейсов Google, возможностью добавления новых тем и точечного переопределения стилей в отдельных проектах и компонентах через общий пакет `@kalex/dsh-core`.

## Impact

Затрагиваются структура корневого репозитория, конфигурационные файлы сборки и проверки кода, каталог правил для агентов `agents/`, новый общий пакет `packages/dsh-core`, а также исходный код, скрипты сборки и тесты пакетов `packages/dsh-agents-router` и `packages/dsh-proxy-provider`. Внешнее поведение плагинов для пользователя и контракты интеграции с оболочкой DSH сохраняются.
