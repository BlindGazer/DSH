## Зачем

При подключение плагина в проект, где есть несколько наборов правила, плагин начинает работать не правило.
Нужно убедится, что в случае наличия нужных файлов и настроект для плагина (agents-router.json), модель будет работать только с правилами роутера.

Допустим мы подключаем плагин в проект, если такая структура

agents/{agents.md и другие корректные файлы для нашего плагина DSH}
.cursor/{разные правила и скилы для курсора в формате mdc или md}
AGENTS.md

При этмо в AGENTS.md в корне проекта описаны правила без учета нашего плагина для папки .cursor
Наша задача если плагин включен, и в проекте есть корректная папка с настройками для плагина, то агент должен видеть только ее.
Допустим если плагин включе и все настроено, то когда агент пытается прочитать файл AGENTS.md в корне, ему вместо его содержимого нужно передать файл в папке agents/, тоже самое если агент поелез в папку .cursor или любую другую с которыми агенты работаю типа .claude, мы должны вместе нее напривать агента в agents/

Т.е. по задумке, в настройки DSH можно включить настройки вида "Запрещать читать корневой agents.md если он не входит в корневую папку с правилами DSH" и в этом случае всегда идет перенаправление на корневой файл в DSH, если выключена, то не запрещаем агенту читать agents.md в корне.
дать возможно указать список таких корных файлов т.к. там могуть быть CLAUDE.md, AGENTS.md и другие файлы агентво.
Тоже самое для папок с правилами, при включение галочки и указание папок .claude/.cursor делаем перенаправление на agents/
