# Spec Delta

## Purpose

Дает пользователю возможность направлять агента к инструкциям DSH вместо файлов инструкций других инструментов и выбранных корневых файлов проекта, а также исключать их дублирующую автоподгрузку в контекст сессии. Ограничение действует только для активного плагина, корректных настроек и включенных пользователем правил.

## ADDED Requirements

### Requirement: Перенаправление применяется только при активном плагине и корректных настройках
Плагин MUST перенаправлять запросы и изолировать инструкции только когда он включен, файл конфигурации роутера прочитан и проверен, а соответствующее правило перенаправления включено.

#### Scenario: Плагин отключен
- **WHEN** агент запрашивает файл, совпадающий с настроенным правилом, но плагин выключен
- **THEN** запрос обрабатывается без перенаправления согласно обычным правилам чтения проекта

#### Scenario: Настройки отсутствуют или некорректны
- **WHEN** плагин включен, но настройки роутера отсутствуют или не проходят проверку
- **THEN** запросы обрабатываются согласно обычным правилам чтения проекта, перенаправление не применяется, а пользователь получает сообщение о некорректных настройках

#### Scenario: Плагин активен и правило включено
- **WHEN** плагин включен, настройки корректны и соответствующее правило включено
- **THEN** совпавший запрос и контекст сессии обрабатываются согласно требованиям изоляции корневых файлов или каталогов

### Requirement: Пользователь может настроить перенаправление и изоляцию корневых файлов инструкций
Плагин MUST позволять включать или выключать перенаправление корневых файлов инструкций и построчно редактировать список имен файлов, к которым применяется правило. Список MUST сопоставляться только с файлами непосредственно в корне проекта (независимо от того, указан ли путь при чтении как относительный или абсолютный) и MUST предотвращать попадание исходного корневого файла в контекст сессии как через инструмент чтения, так и через автоматическую загрузку инструкций рабочей области DSH.

#### Scenario: Построчное добавление имен в настройках проекта
- **WHEN** пользователь редактирует поле списка имен корневых файлов или поле списка корневых каталогов и нажимает клавишу перевода строки для добавления нового имени
- **THEN** поле ввода переносит курсор на новую строку и позволяет ввести несколько имен по одному в строке, а при сохранении пустые строки отбрасываются и список сохраняется без ошибок проверки

#### Scenario: Перенаправление корневого файла при чтении по относительному или абсолютному пути
- **WHEN** активный плагин получает запрос чтения корневого файла из включенного списка по относительному имени или полному пути внутри проекта
- **THEN** вызов чтения выполняется без ошибки доступа к свойствам аргументов, и агент получает содержимое одноименного файла внутри корневого каталога `agents/`, а не исходного файла из корня проекта

#### Scenario: Исключение перенаправляемого корневого файла из базового контекста сессии
- **WHEN** правило перенаправления корневых файлов включено и среда DSH формирует контекст инструкций рабочей области для шага сессии
- **THEN** содержимое корневого файла из списка не попадает в контекст агента в обход роутера, и агент видит только правила из каталога `agents/`

#### Scenario: Перенаправление корневого файла выключено
- **WHEN** агент запрашивает файл из списка, а правило корневых файлов выключено
- **THEN** запрос обрабатывается без подмены согласно обычным правилам чтения проекта

#### Scenario: Запрашивается неуказанный корневой файл
- **WHEN** агент запрашивает корневой файл, имя которого не включено в список
- **THEN** плагин не перенаправляет запрос по правилу корневых файлов

#### Scenario: Файл с таким именем находится не в корне проекта
- **WHEN** агент запрашивает вложенный файл, имя которого совпадает с именем в списке корневых файлов
- **THEN** плагин не перенаправляет запрос по правилу корневых файлов

### Requirement: Пользователь может настроить перенаправление каталогов инструкций
Плагин MUST позволять включать перенаправление выбранных корневых каталогов инструкций и сопоставлять путь файла относительно каждого такого каталога с тем же относительным путем внутри `agents/`.

#### Scenario: Запрошен файл в выбранном каталоге
- **WHEN** активный плагин получает запрос `.cursor/rules/example.mdc`, каталог `.cursor` выбран, а правило каталогов включено
- **THEN** вызов чтения перенаправляется без ошибки изменения аргументов, и агент получает содержимое `agents/rules/example.mdc`, где `rules/example.mdc` является путем относительно выбранного каталога `.cursor`

#### Scenario: Запрошен файл в каталоге, не включенном в настройку
- **WHEN** агент запрашивает файл каталога, который не выбран или правило каталогов выключено
- **THEN** плагин не перенаправляет запрос по правилу каталогов

#### Scenario: Несколько выбранных каталогов содержат одинаковый относительный путь
- **WHEN** запросы из двух выбранных каталогов имеют одинаковый путь относительно каждого каталога
- **THEN** оба запроса направляются к одному и тому же соответствующему пути внутри `agents/`

### Requirement: Перенаправление не раскрывает исходное содержимое при недоступном или небезопасном назначении
Для запроса, совпавшего с включенным правилом, плагин MUST проверять нормализованный путь назначения, включая разрешение ссылок файловой системы, и MUST NOT передавать исходное содержимое, если назначение отсутствует или находится за пределами `agents/`.

#### Scenario: Файл назначения отсутствует
- **WHEN** запрос совпадает с включенным правилом, но соответствующий файл в `agents/` отсутствует
- **THEN** исходное содержимое не передается, а пользователь получает сообщение о недоступной инструкции DSH

#### Scenario: Настроенный путь выходит за пределы каталога DSH
- **WHEN** нормализованный путь назначения или его конечная цель после разрешения ссылок выходит за пределы корневого каталога `agents/`
- **THEN** плагин отклоняет перенаправление, не передает содержимое исходного файла и сообщает о недопустимом назначении

#### Scenario: Запрос к файлу, уже расположенному в каталоге DSH
- **WHEN** агент запрашивает файл внутри `agents/`, к которому уже направлен другой запрос
- **THEN** плагин передает этот файл без повторного перенаправления
