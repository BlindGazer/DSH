## Фаза 2: Нормализация Globs и устойчивый парсер `.mdc`

- [x] **Task 2.1: Реализация утилиты `normalizeGlobs` и `sanitizeFrontmatter`**
  - **Действие:** Создай (или обнови) модуль парсинга/нормализации (например, `src/utils/glob-normalizer.ts`):
    1. Реализуй функцию `sanitizeFrontmatterYaml(rawFrontmatter: string): string`:
       - Построчно проверяй блок YAML регулярным выражением `/^(\s*(?:globs?|paths?)\s*:\s*)(.+)$/i`.
       - Если значение не пустое и не начинается с `[`, `"`, `'`, оберни его в двойные кавычки (предварительно экранировав `"` внутри строки), чтобы YAML-парсер не падал на `*.ts` или `{a,b}`.
    2. Реализуй функцию `splitGlobString(input: string): string[]`:
       - Разбивай строку по запятой `,` **только если** счетчики вложенности `{...}` и `[...]` равны `0`.
       - Для каждого элемента делай `.trim()`, заменяй `\` на `/`, убирай ведущий `./` (а `!./` заменяй на `!`).
    3. Реализуй функцию `normalizeRulePatterns(frontmatter: RawRuleFrontmatter): string[]`:
       - Собери значения из `frontmatter.path`, `frontmatter.paths`, `frontmatter.glob`, `frontmatter.globs`.
       - Для значений из `path`/`paths`, которые НЕ содержат спецсимволов (`*`, `?`, `[`, `{`, `!`): если это путь к папке (например, `src/core`), конвертируй его в `["src/core", "src/core/**"]` для сохранения обратной совместимости.
       - Пропусти все строки через `splitGlobString` и верни уникальный массив `string[]`.
  - **Критерий готовности:** Функции экспортированы, типизированы и не используют сторонних тяжелых зависимостей.

- [x] **Task 2.2: Обновление парсера правил для поддержки `.mdc` и `activationMode`**

    1. Перед передачей текста между `---` в YAML-парсер пропускай его через `sanitizeFrontmatterYaml`.
    2. Если файл не имеет Frontmatter (например, `AGENTS.md` или простой `.md`), не выбрасывай ошибку — возвращай пустой объект метаданных и весь текст как контент.
    3. Вычисляй `activationMode`:
       - Если `alwaysApply === true` (или это корневой `AGENTS.md` / `CLAUDE.md` / `.cursorrules` без `globs`) -> `'always'`.
       - Иначе если `globs.length > 0` -> `'glob'`.
       - Иначе если есть непустой `description` -> `'agent-requested'`.
       - Иначе -> `'manual'`.
  - **Критерий готовности:** Все корректные `.mdc` и `.md` файлы из `examples/demo-cursor` парсятся без исключений. Некавыченный `: ` в значении `description` по-прежнему должен приводить к диагностике разбора YAML.

## Фаза 3: Движок сопоставления путей (`RuleMatcher`)

- [x] **Task 3.1: Реализация glob-матчинга с поддержкой wildcard, `{a,b}`, `matchBase` и `!negation`**
  - **Действие:** Создай или обнови модуль сопоставления путей (например, `src/matcher/rule-matcher.ts`).
    1. Проверь `package.json`: если в проекте уже есть `picomatch` или `minimatch` — используй его. Если зависимостей нет и добавление новых пакетов нежелательно, реализуй чистый конвертер `globToRegExp(pattern: string): RegExp` с поддержкой:
       - `**/*` (ноль или более директорий `(?:.+/)?`), `/**` (всё внутри), `**` (`.*`)
       - `*` (любые символы кроме `/`: `[^/]*`)
       - `?` (`[^/]`)
       - `{a,b,c}` -> `(?:a|b|c)`
       - `[abc]` -> `[abc]`
    2. Реализуй метод `matchesRule(rule: NormalizedRuleMetadata, targetPath: string): boolean`:
       - Нормализуй `targetPath` (POSIX слэши `/`, без ведущего `./` или `/`).
       - Если `rule.alwaysApply === true` -> верни `true`.
       - Если `rule.globs.length === 0` -> верни `false`.
       - Раздели `rule.globs` на `positive` (без `!`) и `negative` (начинаются с `!`, при проверке отрезай `!`).
       - При проверке паттерна: если паттерн не содержит `/` (например, `*.ts` или `*.{ts,tsx}`), проверяй совпадение как с самим `targetPath`, так и с `path.posix.basename(targetPath)` (поведение `matchBase: true`).
       - Верни `true`, если `(positive.length === 0 || matchesAny(positive)) && !matchesAny(negative)`.
  - **Критерий готовности:** Матчер корректно отрабатывает все кейсы из `examples/demo-cursor`.
