# Proposal

## Why

Текущая реализация содержит один устаревший Codex-маршрут, статический каталог моделей и незавершенный staged-рефакторинг. Нужно перейти на пакет OpenAI Hub с единым маршрутом, account-oriented настройками и актуальным каталогом моделей, не усложняя сетевую маршрутизацию.

## What Changes

- **BREAKING** Переименовать пакет и каталог в `@kalex/dsh-openai-hub` и `packages/dsh-openai-hub`. Старый пакет не поддерживать и не мигрировать автоматически; пользователь удаляет его и устанавливает новый.
- Использовать единые ключи: `ServiceKey = openai-hub`, `ProviderRoute = openai-hub`, `RemoteNamespace = openaiHub`.
- Хранить аккаунты в конфигурации `accounts[]`; секреты хранить только в Credential Store.
- Использовать `CredentialRef = openai-hub-<authMethod>-<8-hex-hash(accountId)>`.
- Поддержать `device-code` и `browser-oauth`; пользовательская метка аккаунта задается до OAuth и редактируется позже.
- Использовать lowercase ASCII labels без пробелов: буквы, цифры, дефисы.
- Публиковать один объединенный список моделей под одним маршрутом. Группа провайдера отображается как `OpenAI Hub`, а публичный ID модели: `<accountLabel>/<upstreamModelId>`. В имени модели не повторять `openai-hub/`; полное представление для списка субагентов формируется DSH как `openai-hub/<accountLabel>/<upstreamModelId>`.
- Загружать каталог через авторизованный API после входа и по Refresh в модальном окне. При ошибке сохранять последний успешный каталог, а если его нет, использовать локальный `pi-ai` каталог.
- Показывать отдельный блок и отдельное модальное окно для каждого аккаунта в Settings -> Models.
- Сохранять настройки автообновления лимитов по аккаунтам; по умолчанию выключено. Интервал 5 минут, а для выбранной модели при ближайшем лимите ниже 25 процентов - 1 минута.
- Показывать в статус-баре только лимиты выбранной модели этого провайдера и ее аккаунта. При скрытой странице не выполнять сетевые обновления; после возврата выполнить одно обновление.
- При удалении аккаунта удалять его Credential Store и конфигурационные данные. Удаление последнего аккаунта возвращает fresh-install состояние. Историю не переписывать; старые ссылки помечать устаревшими.
- Не изменять `cordis.patch.yml` без доказанной необходимости.

## Capabilities

### New Capabilities

- `openai-hub`: единый OpenAI Hub capability с аккаунтами, моделями, лимитами и авторизацией.

### Modified Capabilities

Нет.

## Impact

Затрагиваются пакет OpenAI Hub, Host/Remote контракт, shared-модели, Client Settings -> Models, chat quota dock, Credential Store, конфигурация через `configEditor`, тесты и документация. Независимая proxy-маршрутизация и dsh-6 не входят.

Отдельные несвязанные исправления оформляются секцией `Bug fixes`: фон `dsh-modal-card` в OpenAI Hub и workspace-manager, staged-регрессия, опасные debug-логи и остаточные obsolete ProxyMode-ссылки.
