# Дизайн

## Контекст

Исходный проект уже написан на TypeScript и использует строгую проверку типов в `tsconfig.json`. Его манифест задает React 18.3, TypeScript 6 и сборку через tsdown. Монорепозиторий использует актуальный React, TypeScript 7, централизованную конфигурацию Vite и общую библиотеку `@kalex/dsh-core`. Поэтому перенос включает адаптацию структуры и инструментов, а не только копирование файлов. Исходный репозиторий остается нетронутым.

## Цели / нецели

**Цели:**
- Перенести исходные файлы без Git-истории в `packages/dsh-workspace-manager`.
- Сохранить наблюдаемое поведение, инструменты, настройки и защиту каталогов только для чтения.
- Соблюсти архитектуру монорепозитория: TypeScript не ниже 7.0.2, React не ниже 19.3, Vite 8 с React Compiler на Oxc и слои `src/shared`, `src/host`, `src/client` с зависимостями только от shared к host/client.
- Для клиентского кода применять декомпозицию компонентов, хуков, локализации и тестовых идентификаторов из актуальных правил фронтенда.
- Использовать подходящие общие компоненты, хуки, контракты и токены из `@kalex/dsh-core` или расширить core при отсутствии нужного общего примитива; не создавать локальные дубли.
- Соблюсти строгие правила TypeScript, разделение ответственности, неизменяемость и требования доступности и адаптивности интерфейса.
- Переименовать пакет в `@kalex/dsh-workspace-manager`, адаптировать конфигурации и проверки к монорепозиторию.
- Добавить в README пометку об ответвлении и ссылку на исходный проект.

**Нецели:**
- Перенос Git-истории или изменение исходного репозитория.
- Добавление функций плагина, не существующих в исходной версии.
- Изменение формата хранимых данных или публичных идентификаторов без необходимости и проверенной совместимой миграции.

## Решения

- Единственный источник переноса - текущее содержимое локальной папки `D:\GIT\DSH\dsh-plugin-addir`, включая локальные незакоммиченные изменения и необходимые исходные файлы, не добавленные в Git. Код в ней изменялся; клонирование GitHub, установка опубликованного пакета или экспорт только закоммиченной ревизии не заменяют этот источник. GitHub используется только для атрибуции происхождения.
- До переноса зафиксировать исходную ревизию Git и состояние локальных изменений, составить перечень переносимых файлов и исключений. Перенести их в `packages/dsh-workspace-manager`, не включая `.git`, `node_modules`, генерируемые результаты сборки и локальные секреты. По перечню проверить сохранение локальных изменений с учетом целевой адаптации. Исходную папку не изменять.
- Сначала сопоставить текущие модули с целевыми слоями и проверить, какие компоненты, хуки и контракты уже предоставляет `@kalex/dsh-core`; затем переместить или адаптировать код по результатам аудита.
- Сохранить строгую типизацию, уже включенную в исходный `tsconfig.json`, согласовав версию и параметры TypeScript с монорепозиторием. Это не требует переписывать уже строго типизированный код без причины.
- Использовать версию React и типы React, совместимые с актуальным стеком монорепозитория, и заменить tsdown на фабрики `createDshHostViteConfig` и `createDshClientViteConfig` из `configs/vite.base.ts`. Клиентскую обертку загрузчика не писать заново: фабрика добавляет ее через `dshModuleLoaderPlugin`. Сохранить формат и точки входа артефактов, необходимые DSH.
- Разместить модели, DTO и константы в `src/shared`, Node.js/Cordis-код в `src/host`, React-компоненты и клиентские функции в `src/client`; клиентский слой может зависеть от shared, но не наоборот.
- Целевой клиентский контракт определяется текущим запущенным DSH и проверяется через Cordis Inspect. Использовать только объявленные клиентские службы, слоты и общие модули; не предполагать доступность API старой версии и не подключать отсутствующие пакеты ради совместимости. Сохранить наблюдаемое поведение исходного плагина через поддерживаемые точки расширения и его Host API.
- React остается внешним runtime DSH: не включать отдельный React в пакет, проверить загрузку клиентского модуля с общим runtime и не объявлять совместимость с неподтвержденной версией.
- Обновить имя пакета и его ссылки в манифестах, сборочных сценариях, примерах установки и документации. Не переименовывать пользовательские инструменты и ключи хранения без необходимости.
- Сохранить лицензионные и авторские сведения исходного проекта. Указать в README ссылку `https://github.com/keatsyh/dsh-plugin-addir` и явно обозначить проект как ответвление.

## Риски / компромиссы

- Переименование пакета меняет команду установки, но идентификатор bundle, имена инструментов и ключи хранилища следует оставить совместимыми, если их смена не требуется для загрузки.
- Замена tsdown на Vite должна сохранить раздельные клиентские и серверные точки входа, формат публикуемых файлов и декларации типов; это проверяется сборкой и проверкой выпуска.
- Обновление React требует согласования версий `react`, `react-dom` и типов с монорепозиторием и тестовой средой.
- Доступные в `@kalex/dsh-core` UI-примитивы могут отличаться от интерфейса исходного проекта; использовать их следует без изменения пользовательских сценариев.
