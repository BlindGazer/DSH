# Маршрутизация инструкций проекта

## Purpose

Плагин подключает правила проекта к контексту сессии по рабочим путям, предоставляет проектные навыки через DSH и объясняет выбор инструкций.

## Requirements

### Requirement: Поддержка `.mdc` и корректная обработка Frontmatter

Плагин MUST обнаруживать правила `.md` и `.mdc` независимо от регистра расширения и обрабатывать не заключенные в кавычки значения шаблонов в метаданных YAML (`glob`, `globs`, `path`, `paths`). Ошибка разбора одного правила MUST NOT мешать загрузке остальных правил проекта.

#### Scenario: Правило Cursor с некавыченными шаблонами
- **WHEN** плагин обнаруживает файл `.MDC` с `globs: *.ts, src/**/*.tsx` и `alwaysApply: false`
- **THEN** он разбирает два шаблона, не отмечает правило как постоянно действующее и не сообщает об ошибке YAML

#### Scenario: Поврежденные метаданные одного правила
- **WHEN** среди обнаруженных правил есть файл с некорректными метаданными и корректный соседний файл
- **THEN** плагин сообщает о поврежденном правиле и оставляет корректное правило доступным

### Requirement: Поддержка полей `path`, `paths`, `glob` и `globs`

Плагин MUST принимать одиночное значение и список в полях шаблонов, разделять перечисления запятыми вне фигурных и квадратных скобок, нормализовать разделители путей и учитывать шаблоны исключения с префиксом `!`.

#### Scenario: Шаблон с альтернативами
- **WHEN** правило с шаблонами `src/**/*.{ts,tsx}, !src/**/*.spec.ts` проверяется для `src/components/Table.tsx`
- **THEN** плагин выбирает правило для этого пути

#### Scenario: Шаблон с исключением
- **WHEN** те же шаблоны проверяются для `src/components/Table.spec.ts`
- **THEN** плагин не выбирает правило для этого пути

#### Scenario: Шаблон без каталога
- **WHEN** правило с шаблоном `*.mdc` проверяется для `.cursor/rules/general.mdc`
- **THEN** плагин выбирает правило для этого пути

### Requirement: Обнаружение проектных источников по умолчанию

Плагин MUST обнаруживать правила и навыки по выбранному режиму. Настраиваемый корень инструкций задается относительно проекта, по умолчанию это `agents/`; режим по умолчанию `merge`. Дополнительные источники проекта включают корневые файлы `AGENTS.md`, `AGENT.md`, `CLAUDE.md`, `.cursorrules` и поддерживаемые инструкции и навыки в `.cursor/`, `.claude/` и `.codex/`. Обнаруженные корневые файлы MUST отмечаться как постоянно действующие.

#### Scenario: Объединение источников
- **WHEN** выбран `merge` и в проекте есть настроенный корень инструкций, корневой `AGENTS.md` и правила Cursor
- **THEN** каталог плагина содержит правила из всех трех источников, а корневой `AGENTS.md` действует без активных путей

#### Scenario: Запасной каталог по умолчанию
- **WHEN** выбран `merge` или `fallback`, стандартный `agents/` отсутствует, а `.agents/`, корневой `AGENTS.md` и правила Cursor доступны
- **THEN** плагин читает `.agents/`, корневой `AGENTS.md` и правила Cursor

#### Scenario: Запасной режим при доступном настроенном корне
- **WHEN** выбран `fallback` и настроенный каталог инструкций доступен
- **THEN** плагин читает его и не добавляет дополнительные источники проекта

#### Scenario: Строгий режим
- **WHEN** выбран `strict`
- **THEN** плагин не добавляет дополнительные источники и не подставляет `.agents/` вместо отсутствующего `agents/`

#### Scenario: Часть дополнительных источников отсутствует
- **WHEN** выбран режим, предусматривающий поиск дополнительных источников, но `.claude/` или `.codex/` отсутствует
- **THEN** плагин продолжает поиск в остальных источниках

### Requirement: Выбор правил по рабочим путям

Плагин MUST подключать постоянно действующие глобальные правила без рабочих путей. Для правила зоны один и тот же рабочий путь MUST удовлетворять условиям зоны, всех ее родительских зон и самого правила. Ключевые слова зон MUST оставаться подсказками и сами по себе не активировать правила. Диагностика MUST показывать источник правила и причину выбора или исключения для проверяемого пути.

#### Scenario: Вложенная зона
- **WHEN** путь удовлетворяет дочерней зоне и правилу, но исключен шаблоном родительской зоны
- **THEN** правило не подключается, а диагностика указывает исключивший шаблон зоны

#### Scenario: Активный путь во вложенной зоне
- **WHEN** рабочий путь удовлетворяет условиям доступных родительских зон, дочерней зоны и ее правила
- **THEN** правило включается в контекст с указанием источника и применимого пути

#### Scenario: Только ключевое слово
- **WHEN** запрос упоминает ключевое слово зоны, но рабочие пути не соответствуют условиям этой зоны
- **THEN** правила зоны не подключаются по одному ключевому слову

### Requirement: Проверка файловых вызовов до выполнения

Перед поддерживаемыми файловыми вызовами плагин MUST проверить рабочие пути всего пакета вызовов и обновить соответствующие инструкции. Если загружены новые или измененные инструкции, плагин MUST остановить пакет до выполнения и сообщить агенту о необходимости перепланировать вызовы.

#### Scenario: Новый путь активирует правило
- **WHEN** хотя бы один из поддерживаемых файловых вызовов пакета добавляет путь, для которого необходимо подключить новое правило
- **THEN** правило становится доступным в контексте, ни один файловый вызов пакета не выполняется, а агент получает указание пересмотреть действия перед повтором

#### Scenario: Нельзя безопасно завершить проверку
- **WHEN** плагин не может разобрать пакет поддерживаемых файловых вызовов или завершить обнаружение настроенных правил
- **THEN** файловая операция не выполняется, а агент получает причину отказа

### Requirement: Бюджет объема инструкций не ограничивает загрузку

Плагин MUST оценивать объем инструкций и отмечать в состоянии сессии превышение настроенного бюджета токенов (по умолчанию 32 000). Превышение MUST NOT исключать правила из контекста по объему.

#### Scenario: Правила превышают бюджет
- **WHEN** расчетный объем выбранных инструкций превышает настроенный бюджет токенов
- **THEN** состояние сессии отмечает превышение, а выбранные правила остаются в контексте

### Requirement: Проектные навыки доступны по запросу DSH

Плагин MUST предоставлять DSH метаданные доступных проектных навыков, а полное содержимое навыка загружать только по запросу штатного механизма DSH. Проектный навык MUST NOT замещать уже видимый глобальный навык с тем же именем.

#### Scenario: Просмотр списка и вызов навыка
- **WHEN** DSH запрашивает список навыков проекта, а затем загружает выбранный доступный навык по его имени
- **THEN** список содержит описание без тела навыка, а запрос выбранного навыка возвращает его полное содержимое

#### Scenario: Имя уже занято глобальным навыком
- **WHEN** имя проектного навыка совпадает с именем видимого глобального навыка
- **THEN** плагин не публикует проектный навык под этим именем
