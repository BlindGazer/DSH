# Изоляция инструкций проекта

## Purpose

Плагин направляет чтение выбранных файлов инструкций к их заменам в `agents/` и убирает выбранные корневые файлы из автоматических сообщений DSH об инструкциях рабочей области.

## Requirements

### Requirement: Перенаправление применяется только при активном плагине и корректных настройках

Плагин MUST изменять запросы штатного инструмента чтения файлов и фильтровать соответствующие автоматические сообщения только если плагин активен, файл настроек зон `dsh/agents-router.json` найден и прошел проверку, а соответствующее правило включено. Перенаправление чтения MUST использовать `agents/` в корне проекта независимо от каталога, выбранного для обнаружения правил. Изоляция MUST NOT подменять операции записи или редактирования.

#### Scenario: Плагин отключен
- **WHEN** агент запрашивает чтение файла из списка перенаправления при отключенном плагине
- **THEN** запрос обрабатывается без перенаправления согласно обычным правилам чтения проекта

#### Scenario: Настройки отсутствуют или некорректны
- **WHEN** включено перенаправление, но файл настроек зон не найден или не проходит проверку
- **THEN** плагин не подменяет путь чтения, не фильтрует автоматические сообщения и показывает предупреждение в диагностике

#### Scenario: Плагин активен и правило включено
- **WHEN** активный плагин с корректными настройками и включенным правилом получает совпавший запрос чтения, а обнаружение настроено на другой каталог проекта
- **THEN** путь чтения направляется к замене в `agents/`, а не в каталог обнаружения

### Requirement: Пользователь может настроить перенаправление и изоляцию корневых файлов инструкций

Плагин MUST позволять отдельно включать перенаправление корневых файлов и редактировать список имен по одному на строке. Имена MUST сопоставляться только с файлами непосредственно в корне проекта. При формировании контекста сессии плагин MUST удалять соответствующие разделы из автоматических сообщений DSH, сохраняя прочие распознанные разделы. Если разделы нельзя надежно отделить, плагин MUST исключить сообщение целиком.

#### Scenario: Построчное добавление имен
- **WHEN** пользователь вводит несколько имен корневых файлов или каталогов с переводами строки и сохраняет настройки
- **THEN** каждое имя сохраняется отдельным элементом, а пустые строки не сохраняются

#### Scenario: Чтение по относительному или абсолютному пути
- **WHEN** агент запрашивает выбранный корневой файл по имени или полному пути внутри проекта при включенном правиле
- **THEN** инструмент читает одноименный файл из `agents/` и не возвращает содержимое исходного файла

#### Scenario: Смешанное автоматическое сообщение
- **WHEN** DSH передает в контекст распознаваемое сообщение об инструкциях, содержащее выбранный корневой файл и другой файл
- **THEN** при включенном правиле плагин удаляет раздел и запись выбранного корневого файла, сохраняя раздел и запись другого файла

#### Scenario: Нераспознаваемое автоматическое сообщение
- **WHEN** при включенном правиле автоматическое сообщение указывает выбранный корневой файл, но плагин не может разделить его содержимое по файлам
- **THEN** сообщение целиком исключается из контекста

#### Scenario: Правило не применяется к запросу
- **WHEN** правило выключено, имя не указано в списке или совпавшее имя находится во вложенном каталоге
- **THEN** правило корневых файлов не перенаправляет запрос чтения

### Requirement: Пользователь может настроить перенаправление каталогов инструкций

Плагин MUST позволять включать перенаправление выбранных корневых каталогов и сопоставлять путь файла относительно каждого из них с тем же относительным путем внутри `agents/`. Это правило применяется к чтению и MUST NOT само по себе удалять инструкции из автоматических сообщений DSH.

#### Scenario: Чтение в выбранном каталоге
- **WHEN** агент запрашивает `.cursor/rules/example.mdc`, каталог `.cursor` выбран и правило каталогов включено
- **THEN** инструмент читает `agents/rules/example.mdc`

#### Scenario: Совпадение путей в двух каталогах
- **WHEN** агент запрашивает файлы с одинаковым относительным путем в двух выбранных каталогах при включенном правиле
- **THEN** оба запроса направляются к одному пути внутри `agents/`

#### Scenario: Каталог не выбран или правило выключено
- **WHEN** агент читает файл из невыбранного каталога или правило каталогов выключено
- **THEN** правило каталогов не перенаправляет чтение

### Requirement: Перенаправление не раскрывает исходное содержимое при недоступном назначении

Плагин MUST проверять относительный путь назначения, расположение каталога `agents/` внутри проекта и конечную цель после разрешения ссылок файловой системы. Если назначение отсутствует, не является файлом или находится за пределами `agents/`, плагин MUST NOT передавать исходное содержимое.

#### Scenario: Файл назначения отсутствует
- **WHEN** запрос совпал с включенным правилом, но соответствующий файл не найден
- **THEN** плагин отклоняет чтение, сообщает причину и не читает исходный файл

#### Scenario: Путь назначения выходит за пределы каталога инструкций
- **WHEN** путь назначения абсолютный или выводит за пределы `agents/`, либо после разрешения ссылок каталог `agents/` находится за пределами проекта или файл назначения находится за пределами `agents/`
- **THEN** плагин отклоняет чтение, сообщает о недопустимом назначении и не читает исходный файл

#### Scenario: Запрашивается файл, уже расположенный в каталоге инструкций
- **WHEN** агент запрашивает файл внутри `agents/`
- **THEN** плагин не перенаправляет запрос повторно
