# Спецификация OpenAI Hub

## Purpose
OpenAI Hub подключает учетные записи ChatGPT к DSH. Плагин объединяет их модели OpenAI Codex в одной группе, но настраивает модели, учетные данные и лимиты отдельно для каждой записи.

## Requirements

### Requirement: Один маршрут для подключенных учетных записей
Плагин MUST регистрировать один постоянный маршрут моделей `openai-hub` и один сервис обмена между клиентом и сервером (`openaiHub`). Запросы используют сетевое подключение DSH: плагин не настраивает отдельный системный прокси, не требует ключ OpenAI Platform API и не регистрирует инструменты входа для агента.

#### Scenario: Запуск с разным числом записей
- **WHEN** плагин запускается без учетных записей или пользователь подключает несколько записей
- **THEN** маршрут и сервис остаются одними и теми же; записи не становятся отдельными провайдерами

### Requirement: Подключение и повторный вход
Плагин MUST поддерживать вход ChatGPT по коду устройства и через браузер. До добавления записи пользователь задает уникальную метку: от 1 до 32 символов, первая буква строчная латинская, остальные символы могут быть строчными латинскими буквами, цифрами или дефисами. Пользователь может повторно авторизовать существующую запись, не теряя ее настройки.

#### Scenario: Вход по коду устройства
- **WHEN** пользователь начинает вход по коду устройства
- **THEN** плагин показывает код, ссылку на страницу проверки и состояние входа; после успешного подтверждения запись становится подключенной

#### Scenario: Вход в браузере и ручный повтор
- **WHEN** плагин запрашивает адрес обратного вызова после входа в браузере, а обмен по принятому адресу завершается временной сетевой ошибкой, допускающей повтор
- **THEN** пользователь вставляет полный адрес перенаправления в диалог входа и может вручную повторить обмен без повторной вставки адреса

#### Scenario: Отмена незавершенного входа
- **WHEN** пользователь отменяет незавершенный вход или повторную авторизацию
- **THEN** незавершенная попытка прекращается; ранее подключенная запись не заменяется результатом отмененной попытки

### Requirement: Изоляция учетных данных
Плагин MUST хранить секреты только в хранилище учетных данных DSH. Конфигурация содержит настройки и непрозрачную ссылку, зависящую от способа входа и учетной записи, а не полный идентификатор аккаунта. Токены, адрес обратного вызова и необработанные ответы об ошибках не передаются в диагностические сообщения.

#### Scenario: Токен требует обновления
- **WHEN** запросу для выбранной записи нужен новый токен
- **THEN** плагин обновляет и сохраняет токены только этой записи и не передает их клиенту; если действующий вход получить нельзя, запрос к модели отклоняется с сообщением о необходимости входа

### Requirement: Объединенный каталог моделей
Плагин MUST загружать каталог отдельно для каждой записи после входа и по команде обновления. В группе `OpenAI Hub` видны включенные модели подключенных записей. Публичные имя и идентификатор модели имеют вид `<метка>/<исходный идентификатор>`. Префикс маршрута `openai-hub/` может добавляться представлением DSH, например в списке субагентов, но не является частью имени модели в каталоге.

#### Scenario: Выбор и запрос модели
- **WHEN** пользователь выбирает доступную модель и отправляет запрос
- **THEN** запрос использует исходный идентификатор модели, учетные данные соответствующей записи и интеграцию DSH с параметрами рассуждения и вложениями для модели; отключенные или устаревшие модели отклоняются

#### Scenario: Ошибка загрузки каталога
- **WHEN** ответ каталога недоступен или недопустим
- **THEN** плагин сохраняет последний успешный каталог, а до первой успешной загрузки использует встроенный каталог pi-ai; состояние ошибки доступно клиенту отдельно от состояния входа и не подменяет список моделей

### Requirement: Настройки отдельных учетных записей
В разделе моделей DSH плагин MUST показывать отдельный информационный блок и окно настроек для каждой записи. В настройках моделей можно менять порядок, имена в списке настроек и включенность моделей; для непустого каталога хотя бы одна модель должна оставаться включенной. Изменения сохраняются, а при обновлении каталога настройки сохранившихся моделей не теряются.

#### Scenario: Открытие настроек учетной записи
- **WHEN** пользователь открывает окно моделей одной из нескольких записей
- **THEN** окно показывает настройки только этой записи и сохраняет читаемый фон в светлой и темной теме DSH

#### Scenario: Изменение состава каталога
- **WHEN** пользователь сохраняет допустимые настройки либо обновленный каталог содержит как прежние, так и новые модели
- **THEN** настройки применяются к своей записи, новые модели доступны в ее каталоге, а попытка отключить последнюю модель или передать недопустимый список отклоняется

#### Scenario: Переименование записи
- **WHEN** пользователь сохраняет новую допустимую метку
- **THEN** публичные идентификаторы моделей меняются, ссылка на учетные данные остается прежней, а старые ссылки в истории не переписываются

#### Scenario: Удаление записи
- **WHEN** пользователь подтверждает удаление записи
- **THEN** удаляются ее учетные данные, настройки и модели, но история и другие записи не меняются; после удаления последней записи снова доступно начальное действие добавления

### Requirement: Лимиты и кредиты учетной записи
Плагин MUST показывать доступные остатки лимитов, сроки сброса и сведения о кредитах по учетной записи. Индикатор чата относится только к выбранной действующей модели OpenAI Hub и ее записи. Отсутствующие данные не выдаются за нулевой остаток; при ошибке обновления последние успешные данные могут оставаться видимыми.

#### Scenario: Данные доступны, отсутствуют или устарели
- **WHEN** пользователь выбирает модель OpenAI Hub или открывает сведения о записи
- **THEN** показываются доступные данные этой записи с отличием нулевого остатка от отсутствия данных; при выборе другого провайдера или устаревшей модели индикатор чата скрывается

### Requirement: Автоматическое обновление лимитов
Автоматическое обновление MUST быть выключено по умолчанию и сохраняться отдельно для каждой записи. При включении плагин объединяет запросы для одной записи и обычно обновляет ее данные раз в пять минут.

#### Scenario: Низкий остаток выбранной модели
- **WHEN** включено автообновление, а остаток применимого лимита выбранной модели меньше 25 процентов
- **THEN** период обновления этой записи сокращается до минуты; для выбора лимита сначала проверяется часовой, затем пятичасовой, затем суточный период

#### Scenario: Страница скрыта
- **WHEN** страница DSH скрывается и затем снова становится видимой
- **THEN** фоновые запросы приостановлены, пока страница скрыта; при возвращении выполняется одно обновление на запись с включенным автообновлением

### Requirement: Подтверждение применения карточки сброса
Плагин MUST показывать доступные карточки сброса и сроки их действия и требовать явного подтверждения перед запросом, который может израсходовать кредит записи.

#### Scenario: Применение подтверждено
- **WHEN** пользователь выбирает карточку и подтверждает применение
- **THEN** плагин отправляет запрос для выбранной записи и карточки, показывает результат и обновляет доступные сведения

#### Scenario: Результат применения неизвестен
- **WHEN** нельзя достоверно определить, была ли применена карточка
- **THEN** плагин не повторяет запрос автоматически, а при ручном повторе использует ту же карточку и идентификатор запроса

### Requirement: Происхождение проекта
Описание пакета `@kalex/dsh-openai-hub` MUST указывать исходный проект [gooosie/dsh-openai-codex-auth](https://github.com/gooosie/dsh-openai-codex-auth) и сохранять исходные условия лицензии.

#### Scenario: Пользователь проверяет пакет
- **WHEN** пользователь сверяет описание и лицензию пакета
- **THEN** видит ссылку на исходный проект и условия лицензии
