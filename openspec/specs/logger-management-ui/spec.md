# logger-management-ui Specification

## Purpose

Управление записью журнала и настройками отдельных плагинов в общем разделе настроек DSH.

## Requirements

### Requirement: Управление общими и индивидуальными настройками

Раздел MUST редактировать выключатель, порог, лимит и правила очистки глобально и для пакетов, а также общий каталог. Сохранение MUST менять только секцию `dsh-logger` через `configEditor`.

#### Scenario: Индивидуальное управление
- **WHEN** пользователь открывает настройки пакета
- **THEN** видит отдельный выключатель и может задать или сбросить порог, лимит и правила этого пакета, не меняя настройки остальных пакетов

#### Scenario: Наследование
- **WHEN** пользователь сбрасывает переопределения пакета
- **THEN** пакет снова наследует общие параметры, а его собственный выключатель не меняется

### Requirement: Список пакетов и язык

Раздел MUST использовать компоненты `dsh-core` из исходников и язык оболочки DSH.

#### Scenario: Пакет не запросил журнал
- **WHEN** пакет установлен, но не запрашивал журнал и не имеет сохранённого переопределения
- **THEN** он не включается в список; сохранённые переопределения доступны для редактирования

### Requirement: Выбор уровня и правила очистки

Общий порог и порог пакета MUST выбираться из списка; для пакета MUST быть доступно наследование. Для каждого набора правил MUST существовать отдельные коллекции ключей и путей с добавлением и удалением отдельных записей.

#### Scenario: Разделение ключей и путей
- **WHEN** пользователь добавляет ключ `email` и путь `user.email`
- **THEN** они отображаются и сохраняются в разных коллекциях

### Requirement: Состояние формы и ошибки

Интерфейс MUST сохранять по явному действию, блокировать повтор во время запроса и предупреждать о потере правок при перезагрузке. При отказе MUST сохранять введённые значения и не сообщать об успехе.

#### Scenario: Ошибка сохранения
- **WHEN** сервер отклоняет обычное сохранение
- **THEN** введённые значения остаются доступны для исправления, а сообщение можно прочитать и скопировать до явного закрытия

### Requirement: Уведомления о сохранении

Интерфейс MUST различать успешное сохранение, предупреждение и ошибку по тексту и семантическому оформлению `dsh-core`. Ошибка MUST оставаться доступной для выделения и копирования до явного закрытия.

#### Scenario: Копирование ошибки
- **WHEN** пользователь выделяет или копирует текст ошибки
- **THEN** сообщение остаётся доступным, а текст копируется целиком

### Requirement: Ошибки каталога

Отклонённый путь MUST выделяться у поля ввода. Ошибка очистки MUST отображаться как предупреждение после успешного сохранения, а не как отказ сохранить настройки.

#### Scenario: Недопустимый каталог
- **WHEN** сервер отклоняет выбранный путь
- **THEN** интерфейс показывает ошибку рядом с полем и не открывает диалог подтверждения

### Requirement: Подтверждение смены каталога

Перед сохранением другого каталога интерфейс MUST запросить у сервера предварительный просмотр для текущего значения поля. Устаревший ответ MUST игнорироваться. Диалог MUST показывать старый путь, количество контролируемых и посторонних объектов и конкретные объекты удаления; в русской локали подтверждающая кнопка MUST называться "Сменить". Отмена MUST оставлять сохранённые настройки и файлы без изменений.

#### Scenario: Отмена смены пути
- **WHEN** пользователь отклоняет предупреждение
- **THEN** сохранённый путь, старый каталог и настройки пакетов остаются без изменений

#### Scenario: Устаревший просмотр
- **WHEN** пользователь меняет путь, пока проверяется предыдущее значение
- **THEN** ответ для прежнего значения не разрешает сохранение нового пути
