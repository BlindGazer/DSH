## Requirements

### Requirement: Управление настройками

UI MUST изменять глобальные enabled, level, path, maxFileBytes и необязательный sanitizer, а также package policies с enabled, optional level, optional maxFileBytes и optional sanitizer. Все изменения MUST сохраняться только в Config Service dsh-logger через configEditor.

#### Scenario: Переопределение пакета
- **WHEN** пользователь изменяет policy packageName
- **THEN** изменяется только logger Config Service, а Config Service пакета не меняется

### Requirement: Согласование интерфейса и компоненты Core

[HTML-макет](../../docs/logger-settings.html) MUST быть согласован пользователем до замены рабочего интерфейса. Все контролы рабочего интерфейса MUST использовать компоненты dsh-core: SwitchControl, TextField, ThemedSelect, Button и Modal. Новые визуальные примитивы вне Core MUST NOT создаваться при наличии подходящего компонента Core; недостающие возможности MUST расширяться в Core. Компоненты MUST включаться из исходников Core в клиентскую сборку логгера, вместе с необходимыми стилями и без внешнего импорта внутреннего пакета. React Context и hooks MUST NOT входить в независимую библиотеку dsh-logger-core.

#### Scenario: Индивидуальное управление подключёнными плагинами
- **WHEN** пользователь открывает раздел логирования
- **THEN** для каждого подключённого к логгеру плагина видны независимый выключатель и раскрываемые настройки уровня, лимита файла и дополнительных правил санитизации
- **AND** наследование и собственное значение явно различаются, сброс возвращает общие параметры, изменение одного плагина не меняет остальные

#### Scenario: Ошибка сохранения
- **WHEN** сервер отклоняет сохранение
- **THEN** UI показывает ошибку и повторное действие, сохраняет введённые значения и не сообщает об успешном сохранении

### Requirement: Коллекции правил и выбор уровня

Глобальный и индивидуальный уровни MUST выбираться раскрывающимся списком. Sanitizer MUST предоставлять две независимые коллекции keys и paths с добавлением и удалением отдельных записей; смешанное поле MUST NOT использоваться.

#### Scenario: Разделение ключей и путей
- **WHEN** пользователь добавляет ключ email и путь user.email
- **THEN** они отображаются и сохраняются в разных коллекциях без автоматического смешивания

### Requirement: Всплывающие уведомления

Уведомления MUST поддерживать error, warning, info и success с семантическими цветами Core; error MUST отображаться красным. Текст MUST допускать выделение и копирование. Уведомление MUST иметь явное закрытие и MUST NOT исчезать во время чтения или копирования. Стандартный механизм DSH MUST переиспользоваться при подходящем контракте; иначе компонент MUST находиться в Core.

#### Scenario: Копирование ошибки
- **WHEN** пользователь выделяет текст ошибки или нажимает копирование
- **THEN** уведомление остаётся доступным, а полный текст можно скопировать

### Requirement: Client Context

Client MUST предоставлять scoped DshLogger через DSH Client Service и React Context/Provider. Компоненты MUST получать logger через hook и MUST NOT использовать window logger или props-цепочку. При отсутствии Client Service MUST использоваться no-op.

#### Scenario: Действие интерфейса
- **WHEN** компонент вызывает logger hook и записывает событие
- **THEN** запись отправляется без знания destination и packageName

### Requirement: Безопасная смена пути

UI MUST показывать предупреждение, старый абсолютный путь, количество контролируемых и неизвестных объектов и требовать явного подтверждения перед сохранением нового path. Отмена MUST сохранять прежний path и файлы. Подтверждение MUST выполнять очистку только по правилам Host. Подтверждающая кнопка MUST называться "Сменить"; диалог MUST показывать конкретные удаляемые файлы и каталоги вместо общего поясняющего абзаца.

#### Scenario: Отмена смены пути
- **WHEN** пользователь отклоняет предупреждение
- **THEN** Config Service, старый каталог и policies остаются без изменений
