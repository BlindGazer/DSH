# openai-codex-provider Specification

## Purpose
Предоставляет вход ChatGPT и доступ к моделям OpenAI Codex в DSH. Пользователь управляет входом, моделями, сведениями об использовании и сетевым подключением через интерфейс плагина и инструменты агента.

## Requirements

### Requirement: Пользователь может войти через ChatGPT и выйти из учетной записи
Плагин MUST предоставлять безопасный вход ChatGPT через OAuth по коду устройства, отображать состояние входа и позволять завершить сеанс. Учетные данные MUST храниться только в локальном хранилище DSH и не передаваться клиентскому интерфейсу.

#### Scenario: Вход через код устройства
- **WHEN** пользователь начинает вход
- **THEN** плагин показывает код устройства и доверенную ссылку проверки, принимает завершение авторизации, сохраняет учетные данные локально и отображает состояние подключения

#### Scenario: Учетная запись отключена
- **WHEN** пользователь выходит из учетной записи
- **THEN** плагин удаляет локальные учетные данные, отменяет незавершенный вход и перестает считать учетную запись подключенной

#### Scenario: Истекший токен обновляется
- **WHEN** для запроса нужен истекший или близкий к истечению токен
- **THEN** плагин обновляет его через OAuth и сохраняет новый токен в локальном хранилище без показа его клиенту

### Requirement: Плагин предоставляет модели OpenAI Codex в DSH
Пакет `@kalex/dsh-openai-codex-provider` MUST регистрировать модели OpenAI Codex для использования в DSH, передавать запросы с поддерживаемыми уровнями рассуждения и сохранять текущую интеграцию с каталогом моделей и вложениями DSH.

#### Scenario: Пользователь выбирает модель OpenAI Codex
- **WHEN** пользователь выбирает доступную модель OpenAI Codex и отправляет запрос
- **THEN** DSH обрабатывает его через зарегистрированный маршрут с учетными данными ChatGPT и поддерживаемыми настройками модели

#### Scenario: Нет действующего входа
- **WHEN** запрос отправлен без действующих учетных данных
- **THEN** DSH получает контролируемую ошибку отсутствующей авторизации и не отправляет запрос как авторизованный

### Requirement: Пользователь настраивает список моделей
Плагин MUST позволять включать и отключать модели каталога, менять их отображаемые имена и порядок, сохраняя настройки между перезапусками и оставляя включенной хотя бы одну модель.

#### Scenario: Настройки моделей сохранены
- **WHEN** пользователь сохраняет допустимый список моделей
- **THEN** выбор, имена и порядок применяются к каталогу DSH и сохраняются для следующего запуска

#### Scenario: Отключение последней модели
- **WHEN** пользователь пытается отключить последнюю включенную модель или отправляет недопустимый список
- **THEN** настройки не сохраняются, а пользователь получает понятное сообщение об ошибке

### Requirement: Пользователь просматривает использование и сведения о кредитах
Плагин MUST показывать доступные сведения об использовании, лимитах, сроках сброса и кредитах ChatGPT, отдельно обозначая загрузку, ограничение, отсутствие данных и ошибку получения.

#### Scenario: Данные использования доступны
- **WHEN** подключенная учетная запись возвращает данные использования
- **THEN** интерфейс показывает доступные лимиты, остаток и сроки сброса, а также сведения о кредитах

#### Scenario: Данные использования недоступны
- **WHEN** запрос данных завершился ошибкой, ограничен или вернул неполные сведения
- **THEN** интерфейс обозначает недоступность или ограничение и не подменяет отсутствующие сведения нулевыми значениями

### Requirement: Пользователь подтверждает применение карточки сброса
Плагин MUST показывать доступные карточки сброса и их сроки действия и требовать явного подтверждения перед отправкой запроса, который может израсходовать кредит учетной записи.

#### Scenario: Подтверждено применение карточки
- **WHEN** пользователь выбирает карточку, подтверждает действие и запрос завершен
- **THEN** плагин передает выбранную карточку, показывает результат и обновляет доступные сведения

#### Scenario: Результат применения неизвестен
- **WHEN** результат запроса нельзя определить достоверно
- **THEN** плагин сохраняет идентификатор того же запроса и карточку для повторной проверки и не создает новый запрос автоматически

### Requirement: Пользователь выбирает сетевой маршрут запросов
Плагин MUST предоставлять выбор между сетевым подключением DSH и ручным системным HTTP/HTTPS-прокси Windows, не изменяя глобальные настройки сети процесса.

#### Scenario: Маршрут изменен
- **WHEN** пользователь переключает сетевой маршрут
- **THEN** новые запросы используют выбранный маршрут, выполняющиеся запросы завершаются через прежнее соединение, а при неприменимом системном прокси переключение не выдает его за успешное

#### Scenario: Системный прокси не поддерживается
- **WHEN** системный прокси требует неподдерживаемую настройку, например автоматическое обнаружение или PAC
- **THEN** плагин прекращает запрос и сообщает о недоступности маршрута вместо незаметного прямого подключения

### Requirement: Инструменты агента управляют входом
Плагин MUST предоставлять агентам инструменты для начала входа, проверки текущего состояния и выхода, согласованные с пользовательским интерфейсом и локальным хранилищем.

#### Scenario: Агент начинает вход и проверяет результат
- **WHEN** агент вызывает инструмент входа, а затем инструмент проверки состояния
- **THEN** первый инструмент возвращает код устройства и ссылку проверки, а второй сообщает о ходе или результате входа без раскрытия токенов

#### Scenario: Агент завершает сеанс
- **WHEN** агент вызывает инструмент выхода
- **THEN** локальный сеанс удаляется, а последующая проверка состояния сообщает, что вход не выполнен

### Requirement: Перенесенный пакет соответствует архитектуре и интерфейсным правилам DSH
Пакет MUST использовать строгий TypeScript, актуальные React и Vite, разделять код на `src/shared`, `src/host` и `src/client` с однонаправленными зависимостями, а подходящие компоненты, хуки и контракты MUST использовать из `@kalex/dsh-core`.

#### Scenario: Пакет проходит проверки монорепозитория
- **WHEN** пакет проверяется и собирается в монорепозитории
- **THEN** типы проверяются в строгом режиме, клиентская сборка использует React Compiler на Oxc и Vite, а общие возможности не дублируются внутри пакета

#### Scenario: Клиентский интерфейс использует доступные языки и тему DSH
- **WHEN** пользователь открывает интерфейс плагина
- **THEN** строки доступны на английском и русском, интерфейс использует подходящие общие компоненты и токены DSH и сохраняет доступность в поддерживаемых темах и размерах панели

### Requirement: Перенос сохраняет совместимость текущих установок
Новый пакет MUST сохранять необходимые runtime-идентификаторы, контракты обмена, настройки и ключ локального хранения учетных данных, чтобы обновление пакета не теряло вход и пользовательские предпочтения.

#### Scenario: Обновление установленного плагина
- **WHEN** существующая установка заменяется пакетом монорепозитория
- **THEN** плагин распознает сохраненные настройки и учетные данные и продолжает предоставлять прежние клиентские и агентские функции

#### Scenario: Разворачивание пакета
- **WHEN** читатель устанавливает или обновляет пакет по документации
- **THEN** имя пакета указано как `@kalex/dsh-openai-codex-provider`, а необходимые исходные сведения об авторстве и лицензии сохранены
