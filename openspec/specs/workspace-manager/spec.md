## Requirements

### Requirement: Перенесенный пакет сохраняет функции управления каталогами
Пакет `@kalex/dsh-workspace-manager` MUST сохранять пользовательские функции управления дополнительными каталогами исходного плагина, включая интерфейс управления, динамическое добавление и удаление каталогов, контекстное описание подключенных каталогов, режим только для чтения, постоянное хранение настроек и доступные инструменты агента.

#### Сценарий: Пользователь управляет дополнительными каталогами после переноса
- **WHEN** плагин установлен из пакета монорепозитория и пользователь открывает управление рабочим пространством
- **THEN** пользователь может добавлять, изменять и удалять дополнительные каталоги согласно прежним правилам плагина, а существующие данные и настройки плагина обрабатываются совместимым образом

### Requirement: Перенесенный пакет соответствует архитектуре DSH
Пакет MUST использовать строгий TypeScript не ниже 7.0.2, React не ниже 19.3 и Vite 8 с плагином React и компилятором Oxc. Исходники MUST быть разделены на `src/shared`, `src/host` и `src/client`, а зависимости должны идти от shared к host и client. Общие компоненты, хуки и контракты MUST браться из `@kalex/dsh-core` или выделяться туда.

#### Сценарий: Проверяется архитектура пакета
- **WHEN** пакет проверяют после переноса
- **THEN** код расположен в требуемых слоях, строгая проверка типов проходит, клиент собран Vite с Oxc React Compiler, а общие компоненты и контракты не дублируют подходящие возможности `@kalex/dsh-core`

### Requirement: Клиентский код соблюдает архитектуру и проверки DSH
Клиентские компоненты MUST быть функциональными, по одному на файл; состояние, запросы и преобразование данных MUST находиться в отдельных хуках и модулях. Пользовательские строки MUST быть локализованы на английский и русский в `src/shared/constants/localizations`, а селекторы тестов MUST находиться в `src/shared/constants/testId.ts`. Код приложения и тестов MUST избегать `any`, `unknown`, `null`, ненулевых утверждений и подавлений ошибок типов. Состояние и входные данные MUST не мутироваться.

#### Сценарий: Клиентский код проверяется на соответствие правилам
- **WHEN** пакет проходит проверки типов, стиля и клиентские тесты
- **THEN** компоненты, хуки, локализация и тестовые селекторы находятся в предназначенных файлах, а запрещенные небезопасные конструкции отсутствуют

### Requirement: Интерфейс соблюдает дизайн-систему DSH
Клиентский интерфейс MUST использовать подходящие компоненты, примитивы и токены `@kalex/dsh-core` вместо дублирующих собственных решений, MUST применять токены темы DSH и MUST соответствовать правилам дизайна интерфейсов DSH. Если необходимого примитива в `@kalex/dsh-core` нет, он MUST быть добавлен туда, а не реализован отдельно в пакете.

#### Сценарий: Пользователь видит согласованный интерфейс
- **WHEN** пользователь открывает управление дополнительными каталогами
- **THEN** интерфейс использует подходящие общие компоненты и визуальные правила DSH, а также корректно отображается в доступных темах и размерах панели

### Requirement: README указывает происхождение проекта
README пакета MUST явно указывать, что проект является ответвлением `https://github.com/keatsyh/dsh-plugin-addir`.

#### Сценарий: Читатель проверяет происхождение проекта
- **WHEN** читатель открывает README пакета
- **THEN** он видит явную пометку об ответвлении и ссылку на исходный репозиторий
