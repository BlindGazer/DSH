# Спецификация управления рабочими пространствами

## Purpose
Плагин управляет подключенными каталогами рабочего пространства, открывает отдельные сессии в дополнительных рабочих деревьях Git и запускает VS Code на машине DSH.

## Requirements

### Requirement: Редактирование подключенных каталогов
Плагин MUST предоставлять редактор рабочего пространства из его меню и настроек плагина. Редактор сохраняет полный набор подключений для выбранного пространства. Для подключения доступны путь к существующему каталогу на машине DSH, псевдоним, описание и режим только для чтения. Связи хранятся по рабочим пространствам и доступны после перезапуска.

#### Scenario: Изменение рабочего пространства
- **WHEN** пользователь открывает редактор, выбирает каталог встроенным средством выбора, изменяет название пространства или добавляет, правит либо удаляет подключение и сохраняет изменения
- **THEN** редактор применяет сохраненный набор к сессиям этого пространства, не меняя подключения других пространств

#### Scenario: Открытие редактора в разных темах
- **WHEN** пользователь открывает редактор в светлой или темной теме DSH
- **THEN** диалог использует фон темы, а поля и действия остаются читаемыми

#### Scenario: Черновик не заменяет сохраненные данные
- **WHEN** пользователь отменяет редактирование, сохраненный список не удалось загрузить или новый набор содержит недопустимый каталог
- **THEN** прежние подключения остаются неизменными; ошибка загрузки блокирует сохранение, а ошибка сохранения оставляет черновик открытым

### Requirement: Каталоги в контексте и инструментах агента
Плагин MUST поддерживать настроенные на запуске подключения, управление каталогами инструментами `addir_list`, `addir_add` и `addir_remove` и передачу списка каталогов в контекст модели. Регистрация инструментов и передача контекста по умолчанию включены, но могут отключаться отдельно.

#### Scenario: Агент работает с несколькими каталогами
- **WHEN** в сессии есть дополнительные каталоги и включена передача контекста
- **THEN** модель получает список подключений с путями, доступностью записи и заданными псевдонимами и описаниями; неизменный список не дублируется в пределах того же хода

#### Scenario: Разрешение путей и изменение списка
- **WHEN** агент пользуется включенными инструментами управления или обращается к подключению по псевдониму
- **THEN** агент может перечислять, добавлять и удалять дополнительные каталоги; поддерживаются формы `[псевдоним]/путь` и `псевдоним:путь`, а обычные относительные пути разрешаются от основного каталога сессии

### Requirement: Ограничение записи
При включенной проверке, действующей по умолчанию, плагин MUST учитывать канонический путь и отклонять запись или изменение файлов средствами DSH `write`, `edit`, `write_file` и `edit_file` в подключении только для чтения. Проверка не меняет права файловой системы и не распространяется на произвольные команды.

#### Scenario: Символическая ссылка или пересекающиеся каталоги
- **WHEN** операция записи разрешается в цель символической ссылки либо основной каталог входит в более широкое подключение только для чтения
- **THEN** проверка учитывает фактическое расположение; ограничение широкого подключения не делает основной каталог сессии недоступным для записи

### Requirement: Новая сессия в дополнительном рабочем дереве Git
Плагин MUST позволять создать рабочее дерево Git с новой веткой от выбранной локальной или известной Git ветки удаленного репозитория, использовать свободную локальную ветку, создать отслеживающую ветку для `origin` без локального соответствия или открыть существующее дерево того же репозитория. Операция не переключает исходную сессию и не переносит ее незакоммиченные изменения.

#### Scenario: Создание дерева
- **WHEN** пользователь выбирает допустимые исходную ветку, ветку назначения и путь
- **THEN** плагин подготавливает дерево и открывает в нем новую сессию; в стандартном каталоге `.worktrees` плагин добавляет правило в `.gitignore`, если Git еще не игнорирует этот каталог

#### Scenario: Открытие и проверка назначения
- **WHEN** пользователь открывает существующее дерево, в том числе без привязки к ветке, либо пытается создать дерево в занятом или недопустимом месте
- **THEN** зарегистрированное дерево открывается без создания ветки, а недопустимое назначение отклоняется до открытия сессии

#### Scenario: Сессия не открылась после подготовки
- **WHEN** рабочее дерево уже подготовлено, но открытие сессии завершилось ошибкой
- **THEN** повторное действие открывает сессию в подготовленном дереве без его повторного создания

### Requirement: Удаление дополнительного рабочего дерева Git
Плагин MUST удалять только явно выбранное дополнительное дерево, повторно проверяя его путь, привязку к ветке и чистоту. Для дерева с веткой можно запросить слияние в другую локальную ветку перед удалением и непринудительное удаление исходной ветки. Архивация сессии сама по себе не удаляет дерево.

#### Scenario: Успех и частичный результат
- **WHEN** пользователь подтверждает удаление и, при необходимости, слияние и удаление ветки
- **THEN** после успешной проверки и запрошенного слияния удаляется дерево; если Git не может безопасно удалить ветку, она остается, а пользователь получает предупреждение

#### Scenario: Операцию нельзя выполнить безопасно
- **WHEN** выбрано основное или изменившееся после выбора дерево, в выбранном дереве есть незакоммиченные изменения либо слияние конфликтует
- **THEN** плагин не удаляет выбранное дерево и его ветку

### Requirement: Игнорируемые файлы при удалении рабочего дерева

Проверка чистоты MUST учитывать изменения отслеживаемых файлов и неигнорируемые неотслеживаемые файлы. Она не гарантирует сохранность файлов, которые Git игнорирует.

#### Scenario: В дереве остались только игнорируемые файлы
- **WHEN** пользователь удаляет рабочее дерево без других изменений
- **THEN** наличие игнорируемых файлов само по себе не блокирует удаление и эти файлы могут быть удалены

### Requirement: Открытие рабочего пространства в VS Code
При включенной настройке, действующей по умолчанию, плагин MUST позволять запускать VS Code на машине DSH для зарегистрированного рабочего пространства. При поиске файлов рабочего пространства приоритет имеют файлы в корне; вложенный поиск файлов `.code-workspace` и `.workspace` ограничен тремя уровнями, считая корень первым, учитывает `.gitignore` и не следует по ссылкам за пределы рабочего пространства.

#### Scenario: Выбор файла для запуска
- **WHEN** в рабочем пространстве найдено несколько подходящих файлов VS Code
- **THEN** плагин предлагает выбрать один и запускает только выбранный файл; при одном совпадении открывает его автоматически, а при отсутствии совпадений открывает каталог

#### Scenario: VS Code недоступен
- **WHEN** VS Code нельзя запустить на машине DSH или поиск завершается ошибкой
- **THEN** интерфейс сообщает об ошибке вместо того, чтобы подтверждать открытие

### Requirement: Происхождение проекта
Описание пакета MUST указывать, что плагин основан на [keatsyh/dsh-plugin-addir](https://github.com/keatsyh/dsh-plugin-addir).

#### Scenario: Пользователь проверяет происхождение
- **WHEN** пользователь открывает описание пакета
- **THEN** он видит указание на исходный проект и ссылку на него
