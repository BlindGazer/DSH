## Requirements

### Requirement: Детерминированная сериализация

Логгер MUST принимать только JSON-значения: `string`, `number`, `boolean`, `null`, массивы и объекты с JSON-значениями. `undefined` и функции MUST удаляться, `bigint` MUST заменяться строкой `[BigInt]`, `Error` MUST преобразовываться только в `{name,message}`, циклические ссылки MUST заменяться строкой `[Circular]`. Объекты MUST сериализоваться с сортировкой ключей по Unicode code point. `NaN` и бесконечности MUST заменяться `null`, `-0` MUST заменяться `0`. Максимальная глубина MUST быть 8, максимальная длина строки MUST быть 4096 Unicode code points, максимальный размер UTF-8 сериализованного поля `data` MUST быть 64 KiB; примитивные поля envelope в этот лимит не входят. Усечение `data` MUST выполняться сначала по строкам, затем по массивам/объектам в порядке обхода, с маркером `[Truncated]`, пока сериализованное поле `data` не станет не больше 64 KiB. Если готовая JSONL-запись превышает эффективный лимит файла, логгер MUST дополнительно усекать только поле `data` тем же детерминированным алгоритмом, пока вся запись вместе с envelope и переводом строки не станет не больше `maxFileBytes`; примитивные поля envelope MUST сохраняться. Вызов MUST не падать. Если после удаления `data` обязательный envelope все еще превышает лимит, запись MUST быть пропущена, а диагностический счетчик `oversizedRecords` увеличен.

#### Scenario: Несериализуемые данные
- **WHEN** data содержит цикл, функцию или BigInt
- **THEN** результат имеет детерминированные маркеры и не содержит исходное runtime-значение

### Requirement: Базовая и дополнительная санитизация

Базовая защита MUST удалять ключи без учета регистра, содержащие `token`, `authorization`, `cookie`, `password`, `secret`, `credential` или `api_key`. Глобальные и package-specific правила `keys` и `paths` из Config Service dsh-logger MUST только добавлять удаление. `keys` MUST совпадать с ключом на любой глубине, `paths` MUST использовать точки и числовые индексы массивов; wildcard MUST не поддерживаться, а некорректное правило MUST игнорироваться с диагностическим событием без записи исходного значения.

#### Scenario: Правило пути
- **WHEN** path совпадает с вложенным объектом или элементом массива
- **THEN** значение удаляется до сериализации, остальные поля сохраняются

### Requirement: Безопасные пакетные файлы

Путь по умолчанию MUST быть `<resolved DSH profile>/dsh-logger`; пользовательский абсолютный путь MUST поддерживаться. Для default path корнем безопасности является resolved DSH profile. Для custom path корнем безопасности является сам канонический custom path: логгер MUST создавать и изменять только его содержимое и MUST NOT удалять/изменять его родительские каталоги; custom path вне DSH profile разрешен только после явного подтверждения в UI и проверки прав Host. `packageName` MUST быть непустым именем из DSH context, а имя файла MUST строиться заменой `/` на `-` и добавлением `.jsonl`. Каждый Host или Client context MUST содержать ровно один packageName. Host и Client одного пакета MUST использовать одну scoped registration по этому packageName и общий JSONL-файл, различая записи только по `source`. Повторная регистрация того же packageName для Host и Client MUST быть идемпотентной, а logger MUST перестать принимать записи только после выгрузки всех context этого packageName. `packageName` MUST быть валидным именем пакета, предоставленным DSH context или manifest. Logger MUST NOT вводить дополнительные ограничения формата packageName; нормализация MUST сохранять исходное значение, а имя файла строится только после замены `/` на `-`. Путь MUST быть проверен на выход за разрешенный корень до и после realpath; каждый существующий ancestor, каталог и файл MUST быть обычным объектом без symlink. Проверка и открытие MUST выполняться в одной операции Host с повторной проверкой перед заменой файла, чтобы исключить TOCTOU. Для каждого packageName MUST использоваться один файл в корне каталога без подпапок. Host и Client MUST использовать общий файл.

#### Scenario: Файл пакета
- **WHEN** packageName равен `@kalex/dsh-openai-hub`
- **THEN** файл имеет имя `@kalex-dsh-openai-hub.jsonl`

### Requirement: Ротация и атомарность

Глобальный `maxFileBytes` MUST быть целым числом не менее 1024, а policy пакета MAY задавать собственный лимит не менее 1024. При превышении лимита логгер MUST сначала детерминированно усекать поле `data`, удалять самые старые записи и сохранять новую запись, пока полный JSONL-файл остается не больше эффективного лимита. Если после усечения минимальный обязательный envelope записи все еще больше лимита, запись MUST быть пропущена с диагностическим счетчиком `oversizedRecords`. Append и ротация MUST выполняться через один lock-файл в каталоге логов с межпроцессной блокировкой и таймаутом 5 секунд; stale lock старше 30 секунд MUST быть удален после проверки владельца процесса, а при истечении таймаута запись MUST быть пропущена с диагностическим счетчиком. Ротация MUST использовать временный файл в том же каталоге, flush/close и атомарную замену; на Windows ошибка замены при открытом файле MUST оставлять исходный файл неизменным. После сбоя временный файл MUST быть безопасно отброшен при следующей операции.

#### Scenario: Превышение лимита
- **WHEN** новая запись превышает эффективный лимит файла
- **THEN** поле `data` детерминированно усекается до размера, позволяющего сохранить всю JSONL-запись; старые записи удаляются, а файл остается валидным JSONL. Если минимальный envelope все еще больше лимита, запись пропускается с диагностическим счетчиком `oversizedRecords`.

### Requirement: Смена каталога

Смена пути MUST требовать явного подтверждения с показом старого пути и объектов очистки. Host MUST анализировать старый каталог: после успешного сохранения нового пути MUST удалить старые JSONL-файлы подключённых пакетов. Если в старом каталоге были только эти файлы, Host MUST удалить опустевший каталог целиком без рекурсивного удаления. При наличии посторонних файлов или подкаталогов Host MUST удалить только контролируемые JSONL-файлы подключённых пакетов, сохранив остальные объекты и сам каталог. Структура хранения MUST оставаться плоской, без подпапок пакетов; родительские каталоги, корень файловой системы и каталог профиля MUST NOT удаляться. Config Service и policies MUST сохраниться.

#### Scenario: Только логи подключённых плагинов
- **WHEN** пользователь подтверждает смену пути и старый каталог содержит только JSONL-файлы подключённых пакетов
- **THEN** после успешного сохранения конфигурации эти файлы и опустевший каталог удаляются; при отмене или ошибке сохранения они остаются

#### Scenario: Чужой файл
- **WHEN** в старом каталоге есть неизвестный объект
- **THEN** неизвестный объект сохраняется, контролируемые файлы удаляются после подтверждения
