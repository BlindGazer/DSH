# `@kalex/dsh-agents-router` - Маршрутизация правил и навыков проекта для DeepSeek Harness

> English documentation: [README_EN.md](<README_EN.md>)

DSH-плагин V1 для маршрутизации проектных правил по известным рабочим путям и регистрации проектных skills через штатный Skills API DSH. Плагин не запускает отдельный агентный цикл и не пишет служебное состояние в проект или установленную папку DSH.

> Целевая версия - DSH `0.2.2-rc.1` и новее.
>
> Требования обновлены 2026-11-02: строгий Agent Skills, стандартные метаданные, Claude-style `paths`, распознавание каталогов без `/` в `path` и предупреждения о локальных ссылках. Нормативный целевой формат находится в [требованиях](<docs/AGENTS-ROUTER-REQUIREMENTS.md>). `allowed-tools` в V1 должен сохраняться только как метаданные, без изменения разрешений DSH.

## Сценарий 1. Установка локально из исходников в DSH Desktop

Используйте этот сценарий при разработке или локальной установке плагина из папки исходного кода.

### 1. Сборка и проверка плагина

Перейдите в папку с исходниками плагина `<path-to-dsh-agents-router>` и выполните:

```powershell
cd "<path-to-dsh-agents-router>"
pnpm install --registry=https://registry.npmjs.org
pnpm run build
pnpm test
```

> Важно: команда `pnpm run build` обязательна перед загрузкой в DSH, так как она собирает клиентский бандл `lib/client.js` из `src/client/index.jsx` (папка `lib/` находится в `.gitignore`).

### 2. Установка в профиль DSH Desktop

**Windows (PowerShell):**

```powershell
pnpm install -C "$env:USERPROFILE\.dsh\profiles\desktop" "<path-to-dsh-agents-router>"
```

**Windows (CMD):**

```bat
pnpm install -C "%USERPROFILE%\.dsh\profiles\desktop" "<path-to-dsh-agents-router>"
```

**macOS / Linux:**

```bash
pnpm install -C "$HOME/.dsh/profiles/desktop" "/path/to/dsh-agents-router"
```

### 3. Включение плагина в DSH

1. Откройте **DeepSeek Harness Desktop**.
2. Откройте вкладку **Plugins** (слева в боковой панели `Plugins`, не в `Settings`).
3. В окне **Plugins** нажмите иконку обновления сверху справа, рядом с кнопкой **Add Plugin** (если плагина нет в списке).
4. В **Installed plugins** найдите `@kalex/dsh-agents-router` и включите плагин.
5. Откройте любую сессию чата - в верхних вкладках диалога появится вкладка **`Agents Router`**.

## Сценарий 2. Создание релизного пакета `.tgz`, публикация в GitHub и установка

Используйте этот сценарий, чтобы собрать самодостаточный архив `.tgz`, опубликовать версию в GitHub (GitHub Releases / Git tag) и устанавливать плагин на других машинах без клонирования репозитория.

### 1. Создание пакета `.tgz` локально

В корне проекта `<path-to-dsh-agents-router>` выполните:

```powershell
cd "<path-to-dsh-agents-router>"

# Сборка клиентского бандла lib/client.js и упаковка в архив kalex-dsh-agents-router-<version>.tgz
pnpm run build
pnpm pack
```

В корне папки появится файл вида `kalex-dsh-agents-router-1.0.0.tgz` (включающий `src/`, собранный `lib/client.js`, `cordis.patch.yml` и `package.json`).

### 2. Публикация версии в GitHub

```powershell
cd "<path-to-dsh-agents-router>"

# 1. При необходимости обновите версию в package.json (например, 1.0.0 -> 1.0.1)
pnpm version patch --no-git-tag-version

# 2. Пересоберите клиентский бандл и создайте релизный архив .tgz
pnpm run build
pnpm pack

# 3. Зафиксируйте изменения, создайте git-тег и отправьте в GitHub
git add .
git commit -m "release: v1.0.0"
git tag v1.0.0
git push origin main --tags
```

Если у вас установлен GitHub CLI (`gh`), вы можете сразу создать GitHub Release с прикрепленным `.tgz`-пакетом одной командой:

```powershell
gh release create v1.0.0 ./kalex-dsh-agents-router-1.0.0.tgz --title "v1.0.0" --notes "Release v1.0.0"
```

*(Либо загрузите созданный файл `kalex-dsh-agents-router-1.0.0.tgz` вручную на странице **Releases -> Draft a new release** вашего репозитория в GitHub).*

### 3. Установка плагина в DSH из скачанного `.tgz` или напрямую из GitHub

#### Вариант А: Установка из скачанного из GitHub Releases файла `.tgz` (рекомендуется для корпоративных сетей)

Скачайте файл `kalex-dsh-agents-router-1.0.0.tgz` со страницы **Releases** вашего репозитория и выполните:

**Windows (PowerShell):**

```powershell
pnpm install -C "$env:USERPROFILE\.dsh\profiles\desktop" "<path-to-downloads>\kalex-dsh-agents-router-1.0.0.tgz"
```

**Windows (CMD):**

```bat
pnpm install -C "%USERPROFILE%\.dsh\profiles\desktop" "<path-to-downloads>\kalex-dsh-agents-router-1.0.0.tgz"
```

**macOS / Linux:**

```bash
pnpm install -C "$HOME/.dsh/profiles/desktop" "/path/to/downloads/kalex-dsh-agents-router-1.0.0.tgz"
```

#### Вариант Б: Прямая установка из GitHub-репозитория по тегу версии

Если в репозитории закоммичена папка `lib/` (или настроен `prepack`), установить конкретную версию из GitHub можно напрямую:

```powershell
pnpm install -C "$env:USERPROFILE\.dsh\profiles\desktop" "github:<github-owner>/dsh-agents-router#v1.0.0"
```

После установки выполните шаги из секции `3. Включение плагина в DSH`.

## Проект и настройки

Корень проекта фиксируется из `agent.session.header.cwd` при создании сессии. Смена проекта внутри этой сессии не поддерживается - откройте новую сессию с нужным корнем. Корень виден в conversation-вкладке **Agents Router**.

Настройки раздельны для каждого канонического корня проекта и задаются в этой вкладке:

| Настройка | Значение по умолчанию |
| --- | --- |
| Корень инструкций внутри проекта | `agents` |
| Папка правил | `rules` |
| Папка skills | `skills` |
| Основной файл правил | `agents.md` |
| Мягкий бюджет | 16 000 токенов |

Правила и skills берутся из выбранной папки проекта; только JSON настроек, рабочий набор и журнал диагностик хранятся в sidecar под `$DSH_HOME/agents-router/`. Плагин не создаёт файлы проекта автоматически. Конфигурация областей всегда расположена в `{instructionsRoot}/dsh/agents-router.json`, например `agents/dsh/agents-router.json`.

### Пример `agents/dsh/agents-router.json`

```json
{
  "areas": {
    "front": {
      "path": "src/front/",
      "keywords": ["front", "react"]
    },
    "front/admin": {
      "path": "src/front/admin/"
    },
    "back": {
      "path": ["src/api/", "src/core/"],
      "enabled": false
    }
  }
}
```

Области задаются явно; каждый родительский сегмент должен быть объявлен. `keywords` - поисковая подсказка, не условие включения правил. `path` поддерживает строку или массив строк (ИЛИ), папку с завершающим `/`, точный путь и базовые `*`, `?`, `**`; сопоставление без учёта регистра. Фильтры задаются относительно корня проекта.

### Правила

`agents.md` - основное правило соответствующей области. Все Markdown-файлы в `{rulesFolder}` обнаруживаются рекурсивно. Правило может быть без frontmatter; поддерживаемые поля: `path`, `paths` (алиас `path`), `description`, `enabled`. Ссылки на другие правила остаются текстом и не обходятся рекурсивно; правила, совпавшие с несколькими путями, добавляются один раз.

```md
---
path: ["*.ts", "*.tsx"]
description: TypeScript changes
enabled: true
---
Сохраняйте публичные интерфейсы и добавляйте тесты для изменений поведения.
```

Глобальные правила без `path` всегда действуют в сессии проекта; остальные подключаются по рабочему набору. Правила родительской области наследуются дочерними. Диагностика пути не добавляет его в рабочий набор.

### Skills

Формат: `{skillsFolder}/<skill-folder>/SKILL.md` в корне инструкций или доступной области. Используется реестр/каталог/loader DSH; тело загружается при вызове, не при обнаружении. Имя команды берётся из папки: `/review`, `/front-review`, `/front-admin-review`. Требуется непустое `description`; поддерживаются стандартные поля DSH `name`, `whenToUse`, `metadata`, `disable-model-invocation`, `user-invocable` и `enabled`. Поле `name` не меняет имя команды. Конфликты со встроенными/чужими и дубликаты своих имён не скрываются автопереименованием: конфликтующие skills отключаются с диагностикой.

## Использование

1. Откройте в DSH новую сессию с корнем проекта.
2. В conversation-вкладке **Agents Router** проверьте привязанный корень и настройки; при необходимости сохраните их до работы с файлами.
3. Используйте действия **Add / Release** для рабочего набора. Известные пути чтения/записи добавляются автоматически до операции; найденные `glob`/`grep` пути массово не подключаются.
4. Нажмите **Inspect** для диагностики файла без изменения набора. **Refresh** перечитывает структуру и обновляет native Skills catalog. Сохранение настроек обновляет все активные сессии этого проекта.
5. **Reset workset** доступен только при истинном простое агента (включая отсутствие ожидающих сообщений). Он очищает только пути, пересчитывает инструкции и не удаляет историю, не повторяет операции и не откатывает файлы.

Для терминала и внешних инструментов агент может заранее объявить известные пути через штатный инструмент `agents_router_paths(paths)`. Это подсказка/объявление, а не гарантия полного обнаружения файловых обращений процесса.

## Матрица покрытия

| Инструмент | Извлечение пути | V1-поведение / границы |
| --- | --- | --- |
| `read`, `read_image` | `file_path` | Одиночный путь; до выполнения учитываются все известные вызовы в assistant batch |
| `write` | `file_path` | Целевой путь, в том числе новый файл |
| `edit` | `file_path` | Один путь |
| `str_replace_editor` | `path` | Один путь и только распознанная операция |
| `glob`, `grep` | нет | Только поиск; результаты сами не добавляются в набор |
| Терминал, скрипты, прочие инструменты | нет универсального парсера | Только объявленные известные пути; полное покрытие не гарантируется |

При некорректных аргументах известного инструмента или неполном обнаружении настроенных правил файловая операция отклоняется до исполнения. Для внешних проекту путей правила роутера не применяются, доступом продолжает управлять DSH. Поддерживаемые инструменты и версии соответствуют peer dependencies из `package.json`; отдельные операции перемещения/удаления не заявляются этим адаптером.

## Диагностика, история и бюджет

Вкладка показывает источники и причины выбора правил, диагностику обнаружения, области, skills, coverage и метрики. Числа символов точны только для распознанного текста плагина. Оценка токенов - грубая эвристика по символам/скрипту, а не tokenizer выбранного провайдера; предупреждение о превышении мягкого бюджета не блокирует запрос. Вывод не является заполненностью всего контекстного окна.

Сброс рабочего набора не удаляет ранее добавленные сообщения. После изменения файла правило пересчитывается перед следующим запросом; уже загруженные тела skills не переписываются в истории и обновятся при следующем вызове. DSH управляет историей, сжатием и обработкой переполнения; точное восстановление после сжатия и отсутствие старых версий в истории не обещаются.

## Разработка и сборка

Требуются Node.js `>=18` и pnpm `11.28.5` (package-manager pin в `package.json`). Из корня репозитория:

```powershell
pnpm install --registry=https://registry.npmjs.org
pnpm test
pnpm build
```

`pnpm test` импортирует test files в одном процессе, чтобы не полагаться на `node --test` subprocess isolation. `pnpm build` собирает browser client в `lib/client.js` через esbuild. Серверный entry - `src/index.js`, добавляется патчем [`cordis.patch.yml`](<cordis.patch.yml>); UI объявлен как package client export `./client`. Сборка - не отдельное приложение и сама по себе не устанавливает/запускает плагин: загрузку и совместимость требуется проверять штатным DSH plugin loader без копирования файлов в установленный DSH tree.

Демонстрация: [`examples/demo-project/README.md`](<examples/demo-project/README.md>). Требования V1/V2: [`docs/AGENTS-ROUTER-REQUIREMENTS.md`](<docs/AGENTS-ROUTER-REQUIREMENTS.md>).
