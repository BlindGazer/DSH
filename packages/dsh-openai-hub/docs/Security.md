# Безопасность

## Учетные данные аккаунта

- OAuth-токены и полный идентификатор аккаунта хранятся только в DSH Credential Store. Конфигурация плагина содержит несекретные настройки аккаунта: метку, способ авторизации, настройки моделей и автообновления лимитов.
- Credential reference формируется на основе способа авторизации и короткого хеша. Логический формат OpenSpec: `openai-hub-<authMethod>-<8-hex-hash(accountId)>`; внутренний ключ для совместимости с SDK использует подчеркивания, например `openai_hub_device_code_<8hex>` или `openai_hub_browser_oauth_<8hex>`.
- Клиент получает снимок состояния, но не токены и не полный account ID. Секреты и полный ID не должны попадать в ID моделей, логи, ошибки, конфигурацию и пользовательские диагностические сообщения.
- Вход, обновление credential и удаление должны предотвращать восстановление удаленного состояния устаревшими асинхронными операциями.
- Перед открытием следует проверять OAuth-ссылку. Неожиданные URL и исходные детали исключений не передаются пользователю или агент-инструментам.
- Автоматические тесты используют синтетические credentials и подмены OAuth/сетевых сервисов. Реальная авторизация — ручной шаг пользователя.

## Каталог и лимиты

- Запросы каталога и лимитов используют защищенный credential соответствующего аккаунта. Ошибки не должны содержать заголовки авторизации, токены, полный account ID или сырые ответы с секретами.
- При ошибке каталога сохраняется последний успешный результат; до первой успешной загрузки применяется локальный каталог `pi-ai` с отображением ошибки обновления.
- Отсутствующее поле использования/лимита не следует трактовать как нулевое значение.

## Сетевой маршрут

OpenAI Hub использует маршрут сети, настроенный в DSH. В плагине нет выбора proxy-режима, изменения глобального `fetch` или собственного proxy-транспорта. Не следует утверждать, что плагин читает системные настройки прокси.
