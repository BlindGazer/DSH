# Ограничения безопасности и внутренние контракты

## OAuth и учетные данные

- Host хранит JSON учетной записи ChatGPT в локальной ссылке Credential Store `PI_OAUTH_OPENAI_CODEX`. Это сохраняет вход существующих установок.
- Вход, обновление и выход используют одну очередь изменений. Выход инвалидирует незавершенный вход и ожидающие снимки состояния, затем удаляет ссылку; устаревшая операция не должна восстанавливать учетную запись.
- Клиент получает только снимок состояния. Поля access token, refresh token и идентификатор учетной записи не входят в Typed Remote-контракт.
- Ссылка подтверждения OAuth принимается только по HTTPS с узлом `auth.openai.com`. Неожиданные URL и детали исключений не передаются пользователю или в инструмент агента.
- Тесты используют фиктивные учетные данные и замены OAuth/DSH-служб. Настоящая авторизация не запускается.

## Сетевые маршруты

- Режим DSH использует переданную платформой сетевую функцию. Режим системного прокси читает ручные параметры HTTP/HTTPS WinINET текущего пользователя.
- PAC, автоматическое обнаружение, SOCKS, прокси без HTTPS и некорректные значения отклоняются. При ошибке запрос завершается, а прямое подключение не используется как резервный маршрут.
- Каждый запрос и OAuth-операция удерживает аренду выбранного маршрута. После переключения старый транспорт закрывается только после завершения всех операций, начатых через него.
- Плагин не меняет глобальный `fetch` или настройки сети процесса. Логины и пароли, найденные в значении прокси, отклоняются и не попадают в снимок состояния.

## Карточки сброса

- Применение карточки требует подтверждения, допустимого идентификатора карточки и UUID v4 ключа идемпотентности.
- Перед отправкой расходующего запроса Host повторно проверяет доступность выбранной карточки. Сервер отправляет тот же ключ и тот же идентификатор карточки при ручном повторе неопределенного результата.
- Плагин не создает новый запрос автоматически после неопределенного результата. Не повторяйте действие с новым ключом, пока состояние прежнего запроса не выяснено.
- Идентификатор доступной карточки и срок ее действия входят в клиентский снимок для выбора пользователем. OAuth-данные и ключ идемпотентности в снимок не входят.
